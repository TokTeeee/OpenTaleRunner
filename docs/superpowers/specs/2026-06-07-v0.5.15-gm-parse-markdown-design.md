# v0.5.15 — GM 解析 markdown 风格回退 (Parser 增强 + Prompt 加固)

## §1 背景

实际体验中, LLM (GM) 经常不按 PromptBuilder 给的 JSON schema 输出. 它会用 markdown 风格输出结构化段, 例如:

```
1. **时间流逝**: 5分钟
**当前位置**: 光辉城 · 冒险者公会大厅 · 吧台前
**饥饿**: 3 | **口渴**: 2 | **疲劳**: 5 | **卫生**: 1 | **士气**: 0 | **负重**: 0
2. **你的选择**:
- 对白
「我去看看磨坊那边，几只野狗而已，应该不难对付。」
(倾向: 战斗)
- 对白
「米莎太太的失窃案听起来有点蹊跷，我去她那儿走一趟。」
(倾向: 探索/社交)
...
```

整个 raw 文本被 [PMEngine.extractJson](../../client/src/services/engine/PMEngine.ts#L469-L485) 的 fallback 路径塞进 `narrative` 字段, `useSingleSubmit` 把它 addMessage 后, NarrativeArea 通过 `buildNarrativeSegments` 渲染成 PM 气泡, 把 "对白" 误识别为台词.

## §2 目标

让 GM 即便按 markdown 风格输出, 也能被正确解析:

- 时间/位置/状态/选择 字段被提取为 NarrativeResponse 的结构化字段
- 仅纯叙事文本 (去掉结构化段后) 写入 `narrative` 字段
- Prompt 同时加固, 让 LLM 更倾向严格 JSON 输出
- 不破坏现有 JSON / 纯文本 fallback 路径

## §3 范围

| 范围 | 包含 | 排除 |
|---|---|---|
| 改 PMEngine parser | 新增 `extractMarkdownStyleFields`, 集成进 `extractLooseJsonFields` | 重构 `extractJson` 主路径 |
| 改 PromptBuilder | 在 `buildCombinedAdvancePrompt` task 段加硬规则 | 重写 prompt 整体结构 |
| 测试 | 5 个新单元测试 (PMEngine) | E2E 测试 (需真实 LLM) |
| 边界 | markdown 风格 / 混合 / 无标签 | LLM 完全不按规则时的兜底 |

## §4 架构

### 4.1 当前 fallback 路径

`PMEngine.extractJson` (行 469-485):

```
JSON.parse(raw) 成功 → 主路径
JSON.parse 失败 → extractLooseJsonFields → 仍失败 → { narrative: raw }
```

`extractLooseJsonFields` (行 493-518) 只识别 `"key": value` 模式.

### 4.2 增强后的 fallback 路径

```
JSON.parse(raw) 成功 → 主路径 (不变)
JSON.parse 失败:
  ├─ extractMarkdownStyleFields(raw):
  │   ├─ 含 **XXX**: 模式 → 拆分 narrative + 结构化字段 → 返回 Record
  │   └─ 不含 → 返回 null
  ├─ extractLooseJsonFields 剩余的 JSON 片段匹配
  └─ 合并: 优先用 markdown 解析结果, 缺失字段再用 loose 补
```

### 4.3 extractMarkdownStyleFields 设计

输入: GM 原始响应 (raw text)
输出: `Record<string, unknown>` 含以下可选字段:
- `narrative`: 去除结构化标签后的纯叙事
- `time_elapsed`: 提取自 `**时间流逝**: <X>`
- `current_location`: 提取自 `**当前位置**: <X>`
- `consequences.state_changes`: 提取自 `**饥饿**: N | **口渴**: M | ...` 6 字段
- `choices`: 从 `**你的选择**:` 段拆分, 每条 `{text, hint:'', tendency}`

识别规则:
- `**时间流逝**[:：]\s*([^*\n]+)` → time_elapsed
- `**当前位置**[:：]\s*([^*\n]+)` → current_location
- `**(饥饿|口渴|疲劳|卫生|士气|负重)**[:：]\s*(\d+)` → state_changes.<field>
- `**你的选择**[:：]\s*([\s\S]+?)(?=^\s*[^-\s\n]|$)` → 拆分 choices
  - 每个 choice: `- 对白\n「<text>」\n(倾向: <tendency>)` 或简版 `「<text>」`
  - tendency 映射: 战斗→combat, 探索→explore, 社交→social, 投机→opportunistic, 回避→avoid, 未知→explore

叙事清洗: 用 `text.replace(/(\*\*[^*]+\*\*[:：][^\n]*\n?)/g, '')` 去除所有结构化标签行, 再用 `text.replace(/\*\*你的选择\*\*[:：][\s\S]+$/, '')` 去除选择段, `.trim()` 剩余为 narrative.

## §5 数据流

```
GM raw text
    ↓ PMEngine.parseNarrativeWithToolCalls (v0.4 战斗系统)
    ↓ parseToolCalls (拆出 toolcall, 剩余 narrative)
    ↓ extractJson:
        ├─ JSON.parse 成功 → 现有 path
        └─ JSON.parse 失败:
            ↓ extractMarkdownStyleFields (新)
                ├─ 含 markdown 标签 → 拆分
                └─ 不含 → 返回 null
            ↓ extractLooseJsonFields (现有, 继续找 JSON 片段)
            ↓ 合并 markdown + loose 结果
    ↓ NarrativeResponse
    ↓ useSingleSubmit (现有)
        ├─ addMessage({ type: 'pm', content: narrative })
        ├─ game.setChoices(...) ← 现在是真正的 3 个选项
        ├─ character.updateVital(stateChanges) ← 现在实际更新
        └─ game.advanceClock(parseTimeElapsed(timeElapsed)) ← 现在实际推进
```

## §6 错误处理

| 场景 | 行为 |
|---|---|
| 纯 JSON 输出 | 走主路径, 无变化 |
| 纯叙事 (无 markdown) | 走原有 fallback `{narrative: raw}` |
| 完整 markdown 风格 | 走新路径, 字段被正确提取 |
| 部分 markdown (缺选择) | narrative 仍可提取, 缺失字段为默认 |
| LLM 仍以「」台词混入 narrative | narrative 中会含「...」, NarrativeArea 正常渲染为台词 (v0.5.13 dialogue) — 不破坏 |
| 数字非整数 (如 "三") | regex `\d+` 不匹配, 跳过该字段 |

5. `parseNarrativeResponse` 集成: 纯 JSON 输入 → 不破坏现有行为

## §9 风险

| 风险 | 缓解 |
|---|---|
| LLM 改变输出风格后正则失效 | extractLooseJsonFields 仍兜底, narrative 至少可用 |
| 数字格式变 (如 "3.5") | 改 regex `[\d.]+` 即可, 单点修改 |
| 复杂标点混入 (全角冒号 vs 半角) | regex 同时支持 `[:：]` |
| 影响现有 JSON 解析 | 集成点在 fallback 路径, JSON.parse 成功时完全不动 |
| 测试覆盖度不足 | 5 个 case 覆盖核心 + 集成 + 边界 |

## §10 性能

- `extractMarkdownStyleFields` 是 O(n) 字符串扫描, 不引入额外 LLM 调用
- 实际响应 ~2KB, regex 扫描耗时 <1ms, 可忽略
