# v0.6.6 属性架构统一 — 纯计算模式

> **日期:** 2026-06-11
> **版本:** v0.6.6
> **前置:** v0.6.4 (属性分配), v0.6.5 (元素伤害 + 属性分解 tooltip)

## 1. 问题

当前 `character.attributes` 存储的是 **base + 已装备的 attribute_mod**（因为 `applyItemEffects` 直接修改 attributes），但多处代码又从装备 effects 重新计算装备加成，导致双重计算：

| 位置 | 读取方式 | 结果 |
|------|---------|------|
| `CharacterPanel` (面板) | `computeAttributeBreakdowns` → base(含装备) + equipment(重复) | **双重计算** |
| `ActionResolver` (战斗) | `effectiveAttribute` → attributes(含装备) + equipMod(重复) | **双重计算** |
| `applyAttributes` (GM后果) | 直接在 attributes 上 +delta | 在含装备值上操作 |
| 服务端 `PATCH /attributes/spend` | 直接在存储的 attributes 上 +1 | 在含装备值上操作 |

## 2. 设计目标

**`character.attributes` 只存储纯基础值**（不含装备/天赋加成）。所有加成在需要时实时计算。

### 2.1 数据模型

```
character.attributes = { STR: 10, DEX: 10, ... }  // 纯基础值
装备 INT+2 → 不修改 attributes，只从装备 effects 实时计算
天赋 INT+1 → 不修改 attributes，只从 classSkills 实时计算
面板显示 → base(10) + equipment(+2) + classTalent(+1) = 13
战斗计算 → effectiveAttribute(c, 'INT') = 10 + 0(buff) + 2(equip) = 12 (战斗不含天赋)
```

### 2.2 属性值分层

| 层 | 来源 | 计算方式 |
|----|------|---------|
| base | `character.attributes` | 直接读取 (纯基础值) |
| equipment | 装备 effects `attribute_mod` | `getEquipmentAttributeMods(equipped)` |
| classTalent | 职业天赋 `classSkills` | `aggregateClassEffects(character).attributeMods` |
| buff | 战斗 conditions | 战斗时 `effectiveAttribute` 计算 |

**总属性 = base + equipment + classTalent** (面板)
**战斗属性 = base + buff + equipment** (战斗, 不含天赋, 与现有 effectiveAttribute 一致)

## 3. 变更清单

### 3.1 `characterStore.ts` — 移除 `applyItemEffects` 的属性修改

**Before:** `applyItemEffects` 直接修改 `character.attributes`
**After:** `applyItemEffects` 只修改 `elementalResistances`（装备抗性）和 `maxMp`（MP加成），不再修改 attributes

具体：
- 删除 `applyItemEffects` 中 `attribute_mod` 的处理逻辑
- 保留 `elemental_resist` 和 `mp_bonus` 的处理（这些没有纯计算替代，且不在战斗中双重计算）
- 或者：完全移除 `applyItemEffects`，抗性/MP 也改为纯计算

**决策：完全移除 `applyItemEffects`**，所有装备效果统一纯计算。理由：
- 抗性已有 `getEquipmentResistances` 纯计算
- MP加成已有 `getEquipmentMPBonus` 纯计算
- 统一模式，不留隐患

### 3.2 `BackpackModal.tsx` — 移除 `applyItemEffects` 调用

装备/卸下时不再调用 `applyItemEffects`，只修改 `inventory.equipped`。

### 3.3 `DebugModeModal.tsx` — 移除 `applyItemEffects` 调用

生成物品自动装备时不再调用 `applyItemEffects`，只修改 `inventory.equipped`。

### 3.4 `computeAttributeBreakdowns` — 修正 base 含义

`base` 现在就是 `character.attributes`（纯基础值），不再含装备加成，无需反算。

### 3.5 `effectiveAttribute` (ActionResolver) — 已正确

当前 `effectiveAttribute = base + buff + equipMod`，移除 `applyItemEffects` 后 `base` 就是纯基础值，不再双重计算。

### 3.6 服务端 — 迁移：从存储的 attributes 中减去装备加成

**关键问题：** 已保存的角色数据中 `attributes` 可能已含装备加成。需要一次性迁移。

**迁移策略：** 客户端加载角色时，检测并修正：
- 加载角色后，遍历已装备物品的 `attribute_mod` effects
- 从 `attributes` 中减去这些加成，还原纯基础值
- 保存时只保存纯基础值

在 `characterStore.setCharacter` 中加入修正逻辑。

### 3.7 `applyAttributes.ts` — 无需修改

`applyAttributeChanges` 在纯基础值上 +delta，这是正确的（GM 后果改变的是基础属性）。

### 3.8 服务端 `PATCH /attributes/spend` — 无需修改

服务端在存储的 attributes 上 +1，迁移后存储的就是纯基础值，操作正确。

## 4. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 已保存角色 attributes 含装备加成 | `setCharacter` 加载时自动修正 |
| 战斗中抗性/MP 不再通过 applyItemEffects 应用 | `mergeEquipmentBonuses` 已纯计算，不受影响 |
| 装备/卸下后 attributes 不变 | 正确行为，加成通过纯计算体现 |

## 5. 测试计划

1. `computeAttributeBreakdowns` 单元测试 — 装备加成、天赋加成、混合场景
2. `setCharacter` 迁移测试 — 加载含装备加成的旧数据时自动修正
3. `BackpackModal` 装备/卸下测试 — attributes 不变，面板显示正确
4. 战斗 `effectiveAttribute` 测试 — 不再双重计算
5. 现有 `characterStore-allocate` 测试 — 确保不受影响
