# v0.6.5 元素伤害接入战斗 + 元素 Icon 表现

## 背景

v0.6.3 定义了 8 元素武器伤害词条 (wpn_elem_fire 等)，affixPools 中已存在但未接入 ActionResolver。`ELEMENT_ICONS` 已定义但战斗日志未使用。

## 目标

1. 武器元素伤害词条接入 `resolveAttack` 伤害计算
2. 战斗日志中所有元素信息附带 icon

## 设计

### 1. 武器元素伤害接入 resolveAttack

当前 `resolveAttack` 的伤害公式:
```
damage = max(1, d6 + STR_mod + weapon - defense) * QTE
```

改造: 在步骤2(伤害计算)和步骤3(实际生效)之间，增加**元素附加伤害**步骤:

```
步骤2.5: 武器元素附加伤害
  - 从武器 effects 中提取 elemental_damage 类型词条
  - elemental_damage 格式: { type: 'elemental_damage', value: { element: 'fire', bonus: 5 } }
  - 附加伤害 = bonus (固定值，不受 QTE 缩放)
  - 附加伤害受目标该元素抗性减免: elementalBonus * (1 - resistance/100)
  - 总伤害 = 物理伤害 + 元素附加伤害(减免后)
```

新增辅助函数:
```typescript
/** 从武器 effects 提取元素附加伤害 */
export function getWeaponElementalDamage(item: ...): { element: Element; bonus: number } | null
```

### 2. affixPools 词条格式对齐

当前 WEAPON_BUFFS 中元素伤害词条格式:
```typescript
{ id: 'wpn_elem_fire', type: 'attribute_mod', value: { STR: 0 }, ... }
```

需要改为新格式:
```typescript
{ id: 'wpn_elem_fire', type: 'elemental_damage', value: { element: 'fire', bonus: 3 }, ... }
```

精良档位 bonus=3，稀有档位 bonus=5，史诗档位 bonus=8。

### 3. 战斗日志元素 Icon

在日志 message 中，所有元素名称前加 `ELEMENT_ICONS[element]`:

- `resolveAttack`: 元素附加伤害行 → `🔥 火属性附加: 3×(1-40/100)=1.8`
- `resolveAbilityDamage`: 最终伤害行 → `受到 5 🔥火伤害`
- `resolveAbilityDamage`: 抗性行 → `🔥 抗性: 10×(1-40/100)=6`

### 4. 文件改动

| 文件 | 改动 |
|------|------|
| `client/src/services/combat/ActionResolver.ts` | 新增 `getWeaponElementalDamage`; resolveAttack 增加元素附加步骤; 日志加 icon |
| `client/src/data/affixPools.ts` | WEAPON_BUFFS 元素词条改为 `elemental_damage` 格式 |
| `client/src/types/item.ts` | EffectType 追加 `'elemental_damage'` |
| `client/tests/services/combat/ActionResolver.test.ts` | 新增元素伤害测试 |

### 5. 不做的事

- 不改 Ability 的元素伤害逻辑 (已完善)
- 不改 QTE 对元素伤害的影响 (元素附加伤害不受 QTE 缩放)
- 不做多元素武器 (一把武器最多1个元素词条)
- 不做元素伤害暴击
