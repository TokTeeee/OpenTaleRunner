## 0. 背景

v0.5 的核心交互是一条**完整链路**：
**战斗 → EXP 事件 → subscriber 聚合 → PATCH /exp → 服务端算新 level → 写 store → TierUnlockModal 弹 → 玩家选节点 → PATCH /class**（共 7 个状态跃迁）。

这套链路目前**没有任何端到端测试**：
- 单元测试只覆盖单个零件（`grantExp.test.ts` 验 EXP 公式；`subscribeCharacterEvents.test.ts` 验 fetch 调用；`TierUnlockModal.test.tsx` 验 modal DOM；`class.test.ts` 验 effect 聚合）。
- 没有一个测试把这 7 个跃迁穿起来，验证**链路之间的契约**（事件 → 订阅 → fetch → 写 store → modal 弹出 → 选节点 → 写 class → fetch）。

后果：
- v0.5.5 的 AP 规则澄清是单元测试的；不验证上层集成。
- v0.5.6 修的 typecheck/lint 错误里，**没有任何一个会**捕捉到 "PATCH /exp 拿到的 patch 字段名拼错" 这种契约漂移。
- v0.5.4 修的 EXP 触发链断开（v0.5.4 audit Gap #1）正是这种端到端缺位的直接结果。

## 1. 目标

加 1 个集成测试文件，**单一剧本式 it()**，走完 v0.5 主路径的 8 步，作为 v0.5 的"集成回归网"。

非目标（明确不做）：
- 不覆盖战斗引擎本身（`CombatEngine.test.ts` 已经覆盖了）。
- 不覆盖 EXP 公式（`expFormula.test.ts` + `grantExp.test.ts` 已经覆盖）。
- 不覆盖 class effect 聚合（`classEffects.test.ts` 已经覆盖）。
- 不覆盖多人 EXP 共享（v0.6 范围）。
- 不起真实服务端（mock fetch）。

## 2. 设计

### 2.1 文件位置与命名

```
client/tests/integration/levelUpFlow.test.tsx
```

- 放在 `tests/integration/`（与 `guild.test.tsx` / `class.test.ts` 同目录）。
- 命名 `<feature>Flow.test.tsx`，与现有 `guild.test.tsx` 风格一致。
- `.tsx` 因为要挂载 React 组件（`GuildClassModal` + `TierUnlockModal`）。

### 2.2 测试结构

**单一剧本式 it()**（用户拍板的结构）：
- 一个 `describe('v0.5.7 — LevelUp 端到端链路')` + 一个 `it('L1→L5+T2 完整链路')`。
- 内部用 `// Step N: <一句话描述>` 分段。
- 每个 Step 段尾用 `expect(...)` 验证上一步结果 + 当前状态。

### 2.3 链路 8 步的剧本

| # | Step | 实现 | 关键断言 |
|---|------|------|----------|
| 0 | Setup: 创建 L1 角色，无职业，无 classId | 直接 `useCharacterStore.setState({ character: makeChar({level:1, classId:null}) })` | store 状态正确 |

| 11 | cleanup | `unsubscribe()` + 卸载组件 + `eventBus.clear()` | |

### 2.4 Mock 策略

- **fetch mock**: 用 `vi.spyOn(global, 'fetch')` + 自定义 resolver（参考 `subscribeCharacterEvents.test.ts` 的写法）。
  - 路由到 `/api/v1/characters/{id}/exp` → 返 L5 patch。
  - 路由到 `/api/v1/characters/{id}/class` → 返 `{ok: true}`。
  - 其他 URL → 抛错（不应被调用）。
- **不引入 MSW**: 保持与现有 `subscribeCharacterEvents.test.ts` 一致，避免引入新依赖。
- **debounce 调到 200ms**: 加快测试；800ms 反而会慢，且不影响"debounce 合并"的语义验证。

### 2.5 不动 production 代码

- 不修 `subscribeCharacterEvents.ts`（如果发现 bug，**单独开 v0.5.7.1 fix**，不混在测试里）。
- 不修 `GuildClassModal.tsx` / `TierUnlockModal.tsx`。
- 不修 `characterStore.ts`。
- 纯测试代码 + 文档。

## 3. 数据形状

测试中需要构造的角色（参考 `guild.test.tsx` 的 `makeChar`）：

```ts
function makeCharL1(): Character {
  return {
    characterId: 'c1',
    playerId: 'p1',
    name: 'Test',
    race: '人类',
    // ... 其他字段同 guild.test.tsx
    level: 1,
    exp: 0,
    expToNext: 100,
    unspentAttributePoints: 0,
    classId: null,
    classSkills: [],
  };
}
```

warrior T1 节点 ID（用 data/classes.ts 的真实 ID，pattern: `<class>_t<tier>_<slot>`）：
- 战士 T1 共 3 节点：`<warrior>_t1_1` / `<warrior>_t1_2` / `<warrior>_t1_3`
- 选 `warrior_t1_1` 即可
- 战士 T2 共 3 节点：`<warrior>_t2_1` / `<warrior>_t2_2` / `<warrior>_t2_3`
- 选 `warrior_t2_1` 即可
- 测试中不 hard-code 名字，而是用 `getClass('warrior').nodes.find(n => n.tier === 1 && n.slot === 1).id`，避免 spec 漂移

## 4. 错误处理

测试自身出错时：
- `try { ... } finally { unsubscribe(); eventBus.clear(); unmount(); }` 模式保证 cleanup。
- `resetClientStores()` 在 `beforeEach` 调用（参考 `guild.test.tsx`）。
- fetch spy `mockRestore()` 在 `afterEach` 调用。
