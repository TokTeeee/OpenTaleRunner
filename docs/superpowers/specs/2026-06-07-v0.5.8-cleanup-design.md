### 2.3 A-1 — multi-PATCH retry e2e

**新文件**：`client/tests/integration/expRetry.test.tsx`（`.tsx` 保持与 `levelUpFlow.test.tsx` 风格一致，但本测试不挂组件，实际用 `.ts` 也可；为一致性用 `.tsx`）

**测试结构**（1 个 `it`）：
```
Step 0: setup makeChar L1, classId=null, resetClientStores + authToken + endpoint
Step 1: 注册 subscriber (debounceMs: 150)
Step 2: mock fetch 第一次返 503 (failure), 第二次返 200 (success) + body {level:2, exp:0, expToNext:283, unspentAttributePoints:0}
Step 3: emit COMBAT_KILL ×1 (5 exp)
Step 4: await 250ms (debounce + slack)
Step 5: 验 fetch 被叫 1 次, PATCH /exp, 返 503
Step 6: 验 character.level 仍是 1 (失败不写 store)
Step 7: emit COMBAT_HIT ×3 (3 exp)
Step 8: await 250ms
Step 9: 验 fetch 被叫 2 次, 第二次 PATCH /exp 返 200
Step 10: 验 character.level === 2 (applyServerExpGrant 写入)
Step 11: cleanup (unsub)
```

**断言要点**（不验 retry 队列合并，因为当前没这行为）：
- `fetchCalls === 2`（不是 1）
- 两次 PATCH `/exp` 的 body 都合法
- 第一次失败不写 store，第二次成功才写

**CHANGELOG**：
- v0.5.8 段加："Added e2e regression for `subscribeCharacterExpEvents` failure path: assert fetch failure does not write to store, and subsequent events still trigger a fresh PATCH. **Does not** verify true retry queue merging (current implementation discards the failed amount on non-2xx); retry queue logic deferred to v0.6."
