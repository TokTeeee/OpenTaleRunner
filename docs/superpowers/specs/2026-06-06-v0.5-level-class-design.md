# v0.5 — Level / EXP 与职业系统设计

**日期:** 2026-06-06
**分支:** `v0.5-dev`
**状态:** 设计稿已通过(brainstorm §1–§6 全部由用户确认)
**继承自:** v0.4(战斗机制保留,在此基础上新增成长循环)

---

## 0. 概述

v0.5 为 OpenTaleRunner 引入**角色成长循环**:

- **Level-EXP** — 玩家通过战斗结果与叙事行动提交获得经验,升级,并花费未分配属性点。
- **职业系统** — 玩家在**角色创建时**或**任何冒险者公会**选择职业(战士 / 牧师 / 法师 / 盗贼)。每个职业有一套 4 层 × 3 选 1 的技能树(每职业 12 节点,共 48 节点)。
- **服务端权威** — 角色数据存于 `characters` 表的 JSON blob;v0.5 在 Pydantic 模型上新增字段并加入严格校验。无需 DB 迁移。

三个里程碑:**v0.5.1 Level-EXP → v0.5.2 职业 → v0.5.3 公会**。

## 2. 数据模型

### 2.1 Character 新增字段(client + server 对称)

```typescript
// client/src/types/character.ts (增量)
export interface Character {
  // ... 既有字段保留 ...
  level: number;                       // [1, 20],默认 1
  exp: number;                         // 当前级累计 EXP
  expToNext: number;                   // 服务端下发(避免客户端漂移)
  unspentAttributePoints: number;      // 0-20 自由分配池
  classId: string | null;              // null = 无职业
  classSkills: ClassSkillNode[];       // 已解锁节点(按 classId+nodeId 去重)
}

export interface ClassSkillNode {
  classId: string;          // 冗余存,便于按职业过滤
  nodeId: string;           // 形如 'warrior_t1_2'
  unlockedAt: number;       // worldDay,时间线用
}
```

```python
# server/models/character.py (增量)
class ClassSkillNode(BaseModel):
    classId: str
    nodeId: str
    unlockedAt: int


class CharacterResponse(BaseModel):
    # ... 既有字段保留 ...
    level: int = 1
    exp: int = 0
    expToNext: int = 100            # 服务端权威
    unspentAttributePoints: int = 0
    classId: Optional[Literal['warrior', 'cleric', 'mage', 'thief']] = None
    classSkills: list[ClassSkillNode] = []
```

**老存档迁移**(`server/repositories/character_repo.py` → `_migrate_v04_to_v05`):
老角色自动补 `level=1, exp=0, expToNext=100, unspentAttributePoints=0, classId=None, classSkills=[]`。不删老字段。每次读写都跑一次,idempotent。

### 2.4 层级选择派生函数

"玩家是否需要在 T2/T3/T4 做选择"是**纯派生** — 不存标志位,无并发竞争:

```typescript
// client/src/services/class/classService.ts
export function pendingTierChoice(character: Character): 2 | 3 | 4 | null {
  if (!character.classId) return null;
  const TIER_UNLOCK: Record<2|3|4, number> = { 2: 5, 3: 10, 4: 15 };
  const def = getClass(character.classId);
  if (!def) return null;
  for (const tier of [2, 3, 4] as const) {
    if (character.level >= TIER_UNLOCK[tier]) {
      const has = character.classSkills.some(n =>
        def.nodes.find(d => d.id === n.nodeId)?.tier === tier
      );
      if (!has) return tier;
    }
  }
  return null;
}
```

T1 在玩家**选定职业时**直接写入 `classSkills`(无需 modal)。

### 2.5 服务端权威字段

- `level / exp / unspentAttributePoints / classId / classSkills` 经 `PATCH /api/v1/characters/{id}/...` 写入并严格校验。
- 服务端总是从 `level` 重算 `expToNext = round(100 * level^1.5)` 并写回(防止客户端漂移)。
- `level` 限定 [1, 20];`classSkills` 长度限定 `min(floor(level/5) + 1, 4)`(L1=1, L5=2, L10=3, L15=4, L20=4)。
- 属性钳制从 `[3, 18]` 扩到 `[1, 20]`。

### 2.6 明确**不**存的字段

- 技能经验 / 技能等级(仅二元)
- 层级偏移(T1-T4 固定为 L1/L5/L10/L15)
- 副职业 / 杂交职业元数据
- 职业等级(职业与角色 level 同步)

## 3. Level-EXP 服务

### 3.1 升级公式

```typescript
// client/src/services/level/expFormula.ts
export const MAX_LEVEL = 20;
export const EXP_PER_LEVEL_BASE = 100;

export function expToNext(level: number): number {
  if (level >= MAX_LEVEL) return Infinity;     // L20 满级,UI 灰显
  return Math.round(100 * Math.pow(level, 1.5));
}

// 速查表
// L1→2:100  L2→3:283  L3→4:520  L4→5:800   L5→6:1122
// L6→7:1487 L7→8:1890 L8→9:2331 L9→10:2810 L10→11:3324
// L11→12:3873 L12→13:4457 L13→14:5074 L14→15:5724
// L15→16:6407 L16→17:7123 L17→18:7870 L18→19:8650
// L19→20:9462
// L1→20 累计 ≈ 81 800 EXP
```

服务端 `server/services/exp_formula.py` 镜像同一公式;**服务端权威**。

### 3.2 EXP 来源

| 来源 | 触发点 | 基础 EXP | 难度乘数 | 触发代码 |
|---|---|---|---|---|
| **战斗击中** | ActionResolver 命中时 | 5 | ✓ | `ActionResolver.resolveAttack` 命中后 emit `combat.hit` |
| **战斗击杀** | 目标 HP 归 0 | 20 | ✓ | `ActionResolver.applyDamage` 触发击杀检测,emit `combat.kill` |
| **战斗胜利** | `allEnemiesDead` | 30 | ✓ | `CombatView` 检测 `allEnemiesDead`,emit `combat.end` ('victory') |
| **战斗失败** | `allPlayersDead` | 10 | ✓ | 同上,'defeat' 路径(安抚分,鼓励继续玩) |
| **战斗逃跑** | `beginResolving('flee')` | 0 | — | 不授 |
| **叙事提交** | `useActionSubmit` 成功 | 2 | — | PM 引擎返回 narrative 后调 `grantExp` |

难度乘数(读 `currentDifficulty`):

```typescript
const DIFFICULTY_MULT: Record<Difficulty, number> = {
  easy: 0.5, normal: 1.0, hard: 1.5, deadly: 2.0,
};
// final = floor(base * mult)
```

### 3.3 grantExp 纯函数

```typescript
// client/src/services/level/grantExp.ts
export interface GrantExpResult {
  character: Character;
  leveledUpTo: number[];   // 触发的等级列表(可能多级连跳)
  totalAwarded: number;    // 实际消耗的 EXP(满级截断后)
}

export function grantExp(character: Character, amount: number,
                         difficulty: Difficulty): GrantExpResult {
  if (character.level >= MAX_LEVEL || amount <= 0) {
    return { character, leveledUpTo: [], totalAwarded: 0 };
  }
  const final = Math.floor(amount * DIFFICULTY_MULT[difficulty]);
  let { level, exp } = character;
  let pool = exp + final;
  let consumed = 0;
  const leveledUpTo: number[] = [];
  while (level < MAX_LEVEL) {
    const need = expToNext(level);
    if (pool < need) break;
    pool -= need;
    consumed += need;
    level += 1;
    leveledUpTo.push(level);
  }
  if (level >= MAX_LEVEL) pool = 0;

  // 属性点同步
  const unspentAttributePoints =
    character.unspentAttributePoints + leveledUpTo.length;

  return {
    character: { ...character, level, exp: pool, unspentAttributePoints },
    leveledUpTo,
    totalAwarded: consumed,
  };
}
```

**不变量:**
- `level` 单调不减(仅 +1 on level up)
- `exp < expToNext(level)`(满级后锁 0)
- 单次 grantExp 可能连跳多级;每次 +1 unspentAttributePoint
- unspentAttributePoints 上限隐式为 MAX_LEVEL=20 → 最多 19 次发放

### 3.4 属性点分配

```typescript
characterStore.spendAttributePoint(attr: AttributeName)
  → updateAttributes({ [attr]: current[attr] + 1 })
  → unspentAttributePoints -= 1
  → PATCH /api/v1/characters/{id}/attributes/spend
```

**属性范围 [1, 20]**,客户端与服务端共同钳制。L20 仍可分配历史存的属性点,但 `grantExp` 不再发放新点。

### 3.5 EventBus 钩子接入

| 系统 | 接入位置 | 事件 |
|---|---|---|
| **ActionResolver** | 命中 / 击杀 末尾 | emit `combat.hit` / `combat.kill` |
| **CombatView** | 战斗结束分支 | emit `combat.end` with outcome |
| **useActionSubmit** | narrative 接收后 | emit `narrative.submit` |
| **characterStore** | 订阅上述事件 | `grantExp(...)` → set state |

**事件流:**

```
ActionResolver  ──emit──>  EventBus  ──subscribe──>  characterStore
useActionSubmit ──emit──>    "           "          characterStore
CombatView     ──emit──>    "           "          characterStore
```

走 EventBus(而非直接调用)是因为 `grantExp` 需要读 `currentDifficulty`(全局)+ 写 characterStore;解耦后测试可在事件边界 mock。

### 3.6 持久化时机

- characterStore 任意字段写 `level / exp / unspentPoints` → debounce 500ms → `PATCH /api/v1/characters/{id}` 全量
- **升级瞬间**立即单独 PATCH(不可丢)
- 失败 3 次重试(指数退避),仍失败则 localStorage 兜底
- 服务端 422 → 客户端回滚 + 强制 reload(防漂移)

### 4.2 ClassEffectAggregator(核心纯函数)

```typescript
// client/src/services/class/classEffects.ts
export interface ClassBonus {
  attributeMods: Partial<Attributes>;     // { STR: 2, CON: 1, ... }
  hpMaxBonus: number;
  mpMaxBonus: number;
  dodgeThresholdBonus: number;           // 累加,负数降低门槛
  damageModifier: number;                // 累加 +0.1 + 0.15 = 0.25
  expBonus: number;                      // 累加
  qteToleranceMs: number;
}

export const EMPTY_CLASS_BONUS: ClassBonus = {
  attributeMods: {}, hpMaxBonus: 0, mpMaxBonus: 0,
  dodgeThresholdBonus: 0, damageModifier: 0, expBonus: 0, qteToleranceMs: 0,
};

export function aggregateClassEffects(character: Character): ClassBonus {
  if (!character.classId) return EMPTY_CLASS_BONUS;
  const def = getClass(character.classId);
  if (!def) return EMPTY_CLASS_BONUS;
  const bonus: ClassBonus = { ...EMPTY_CLASS_BONUS };
  for (const node of character.classSkills) {
    const def2 = def.nodes.find(n => n.id === node.nodeId);
    if (!def2) continue;  // 防御性:跳过无效节点
    applyEffect(bonus, def2.effect);
  }
  return bonus;
}
```

**注入点**(订阅者 / 直接调用):

| 位置 | 注入方式 |
|---|---|
| `attributes` 计算 | `finalAttr = character.attributes + bonus.attributeMods` |
| `maxHp` 计算 | `finalMaxHp = character.maxHp + bonus.hpMaxBonus` |
| `maxMp` 计算 | `finalMaxMp = character.maxMp + bonus.mpMaxBonus` |
| 战斗伤害 | `finalDmg = baseDmg * (1 + bonus.damageModifier)` |
| 命中门槛 | `finalThreshold = threshold - bonus.dodgeThresholdBonus` |
| EXP | `finalExp = baseExp * (1 + bonus.expBonus)` |
| QTE 窗口 | `finalWindowMs = baseWindowMs + bonus.qteToleranceMs` |

**ClassBonus 是派生值,不写回 `character` 状态** — 避免双源真相问题。

```python
# server/services/class_validator.py
ALLOWED_CLASSES = {'warrior', 'cleric', 'mage', 'thief'}
NODE_ID_RE = re.compile(r'^(warrior|cleric|mage|thief)_t[1-4]_[1-3]$')


def _expected_node_count(level: int) -> int:
    """L1=1, L5=2, L10=3, L15=4, L20=4(上限)"""
    if level < 5: return 1
    if level < 10: return 2
    if level < 15: return 3
    return 4


def validate_class_update(char: dict, new_class_id: str | None,
                          new_class_skills: list[dict]) -> None:
    if new_class_id is not None and new_class_id not in ALLOWED_CLASSES:
        raise HTTPException(422, f"invalid classId: {new_class_id}")

    expected = _expected_node_count(char.get("level", 1))
    if len(new_class_skills) > expected:
        raise HTTPException(422,
            f"too many class skills ({len(new_class_skills)} > {expected})")

    for node in new_class_skills:
        nid = node.get("nodeId", "")
        if not NODE_ID_RE.match(nid):
            raise HTTPException(422, f"invalid nodeId format: {nid}")
        if node.get("classId") != new_class_id:
            raise HTTPException(422, f"node classId mismatch")

    current = char.get("classId")
    if current is not None and current != new_class_id:
        raise HTTPException(422, "classId is locked in v0.5 (cannot change class)")

    if new_class_id is not None and len(new_class_skills) == 0:
        raise HTTPException(422, "must have at least T1 node when choosing class")
```

**服务端不校验 effect 字段** — 那由客户端负责。服务端校验: classId allowlist、节点数量、nodeId 格式、classId 锁定。

### 5.4 新路由

```python
# server/routers/character_router.py (新增)
from services.class_validator import validate_class_update
from services.exp_formula import exp_to_next, MAX_LEVEL


@router.patch("/{char_id}/exp")
async def grant_exp(char_id: str, body: ExpGrantRequest,
                    repo=Depends(get_character_repo),
                    player_id=Depends(get_current_player)):
    """
    客户端 grantExp 后调用. 服务端:
    1. 校验授权 (角色属于 player_id)
    2. 用服务端公式计算新 level / exp
    3. 写回 (level 不能降, expToNext 强制重算)
    """
    char = await repo.get(char_id)
    if not char:
        raise HTTPException(404, "Character not found")
    if char.get("playerId") != player_id:
        raise HTTPException(403, "Not your character")

    new_level, new_exp = apply_exp_formula(
        char["level"], char["exp"], body.amount, body.difficulty
    )
    attr_points = char.get("unspentAttributePoints", 0) + (
        max(0, new_level - char["level"])
    )
    patch = {
        "level": new_level,
        "exp": new_exp,
        "expToNext": exp_to_next(new_level),
        "unspentAttributePoints": attr_points,
    }
    await repo.update(char_id, {**char, **patch})
    return patch


@router.patch("/{char_id}/class")
async def set_class(char_id: str, body: ClassSetRequest,
                    repo=Depends(get_character_repo),
                    player_id=Depends(get_current_player)):
    """
    创建时选职业 或 公会选职业 时调用.
    服务端: 校验 classId 合法 / 未锁定 / 节点 ID 合法.
    """
    char = await repo.get(char_id)
    if not char:
        raise HTTPException(404, "Character not found")
    if char.get("playerId") != player_id:
        raise HTTPException(403, "Not your character")

    validate_class_update(char, body.classId, body.classSkills)
    patch = {"classId": body.classId, "classSkills": body.classSkills}
    await repo.update(char_id, {**char, **patch})
    return patch


@router.patch("/{char_id}/attributes/spend")
async def spend_attribute_point(char_id: str, body: AttributeSpendRequest,
                                 repo=Depends(get_character_repo),
                                 player_id=Depends(get_current_player)):
    """
    玩家在 CharacterPanel 点 +1 时调用.
    """
    char = await repo.get(char_id)
    if not char:
        raise HTTPException(404, "Character not found")
    if char.get("playerId") != player_id:
        raise HTTPException(403, "Not your character")
    if char.get("unspentAttributePoints", 0) <= 0:
        raise HTTPException(400, "no unspent points")
    if body.attribute not in ("STR", "DEX", "CON", "INT", "WIS", "CHA"):
        raise HTTPException(400, "invalid attribute")
    attrs = char.get("attributes", {})
    new_val = min(20, attrs.get(body.attribute, 10) + 1)
    attrs[body.attribute] = new_val
    await repo.update(char_id, {
        **char,
        "attributes": attrs,
        "unspentAttributePoints": char["unspentAttributePoints"] - 1,
    })
    return {
        "attributes": attrs,
        "unspentAttributePoints": char["unspentAttributePoints"] - 1,
    }
```

### 5.5 服务端公式镜像

```python
# server/services/exp_formula.py
MAX_LEVEL = 20


def exp_to_next(level: int) -> int:
    if level >= MAX_LEVEL:
        return 0  # 客户端用 Infinity;服务端用 0
    return round(100 * (level ** 1.5))


def apply_exp_formula(level: int, exp: int, amount: int,
                      difficulty: str = 'normal') -> tuple[int, int]:
    """
    同步客户端 grantExp 逻辑,返回 (new_level, new_exp).
    """
    mult = {'easy': 0.5, 'normal': 1.0, 'hard': 1.5, 'deadly': 2.0}.get(difficulty, 1.0)
    final = int(amount * mult)
    if level >= MAX_LEVEL or final <= 0:
        return (level, exp)

    pool = exp + final
    while level < MAX_LEVEL:
        need = exp_to_next(level)
        if pool < need:
            break
        pool -= need
        level += 1
    if level >= MAX_LEVEL:
        pool = 0
    return (level, pool)
```

**测试**(`server/tests/test_exp_formula.py`):镜像 vitest 单元测试,每个 case 一一对应。

### 5.7 写入合并策略

- 客户端 `characterStore` 任意字段变更 → debounce 500ms → `PATCH /api/v1/characters/{id}` 全量

- 服务端返回 422 → client 回滚 + 强制 reload(防漂移)

### 6.2 跨切面关注

#### 性能

- `aggregateClassEffects` 在每次战斗/角色展示都跑;O(N) where N ≤ 5(最多 5 节点)。开销可忽略。
- CharacterPanel 升级条:单纯读 `character.level/exp/expToNext`,不重计算。
- EventBus 订阅 characterStore:3 个 emit 源(combat.hit / combat.kill / combat.end / narrative.submit),单次战斗总计 < 50 事件,开销忽略。

#### 国际化(i18n)

- 4 职业的 `name` / `description` / 节点 `name` / `description` 都用**中文**(现有项目中文为主)
- 故事书 NPC 对话也中文
- 后续 v0.6 接 i18n 时,把这些字符串提到 `locales.ts`

#### 可访问性(A11y)

- 升级 toast 配 ARIA live region
- TierUnlockModal 焦点陷阱 + ESC 取消(取消 = 不学,节点不写入)
- ClassSkillTreeView 网格结构,键盘 Tab 可达
- 颜色区分职业(amber/gold/indigo/emerald)配图标 + 文字,色盲友好

- 403 鉴权 → 强制 logout
- 网络失败 → silent retry + localStorage 兜底,下次打开时上报

### 6.4 CHANGELOG 草稿(v0.5 段,英文)

```markdown
## v0.5

This release adds the **character growth loop** — level/EXP progression, free
attribute point allocation, and a class system with tiered skill trees awarded
at Adventurer's Guilds.

### Level & EXP
- `expToNext(level) = round(100 * level^1.5)`; cap L20
- EXP sources: combat hit (+5), combat kill (+20), victory (+30),
  defeat (+10 consolation); narrative submit (+2)
- Difficulty multiplier: easy ×0.5, normal ×1, hard ×1.5, deadly ×2
- +1 unspent attribute point per level-up; pool-style allocation in CharacterPanel
- Attribute range widened [3, 18] → [1, 20]
- New endpoints: `PATCH /characters/{id}/exp`,
  `PATCH /characters/{id}/attributes/spend`

### Class System
- 4 base classes (warrior / cleric / mage / thief), each with a 4-tier × 3-pick-1
  skill tree (12 nodes / class, 48 total)
- Tier unlock: T1 at class choice, T2 at L5, T3 at L10, T4 at L15
- Class choice at character creation (new Step 7) **or** at any Adventurer's Guild
- Class is locked once chosen (no reclassing in v0.5)
- `ClassEffectAggregator` computes passive bonuses (attribute_mod, hp_max,
  damage_mod, dodge_threshold, exp_bonus, qte_tolerance) from unlocked nodes
- New endpoint: `PATCH /characters/{id}/class` with strict server validation
- Storybook ships 1 guild (starter village); dynamic generation deferred to v0.6

### Server
- No DB migration (data is JSON blob); `_migrate_v04_to_v05` is idempotent
  field backfill on every read/write
- New `class_validator` with Literal classId, regex nodeId format, level-aware
  expected node count, and classId-locked enforcement
- New `exp_formula` mirrors client formula as authoritative

### Test
- 4 × Tier-1 classes, 12 nodes each, with class-effect unit tests
- Tier unlock flow: L1 / L5 / L10 / L15 / L20 boundaries
- E2E: create with class → fight → L5 → tier modal → damage increase verifiable
```

### 6.7 回滚策略

| 里程碑 | 回滚手段 |
|---|---|
| v0.5.1 | 客户端 `classId` 默认 `null`,回滚后老客户端读到的"无 classId" 字段会被静默忽略(TS 字段是可选)。服务端 `_migrate_v04_to_v05` 是 idempotent,回滚不需要反向迁移。 |

| v0.5.3 | Guild 移除:故事书删除 `adventurer_guild_1` 条目即可,无破坏性。 |

**所有回滚都是"前向兼容"** — 老客户端读新存档不会崩(新字段忽略);新客户端读老存档会自动补默认(`_migrate_v04_to_v05`)。

### 6.8 风险与未决

| 风险 | 严重度 | 缓解 |
|---|---|---|
| **ClassEffect 类型扩展漂移**(v0.6 加新 effect 类型时老客户端不识别) | 中 | 客户端 effect handler 用 `switch + default: warn`,未识别的不应用并 log |
| **EXP 客户端/服务端公式漂移** | 中 | 服务端权威;422 时强制 reload;CI 加服务端公式测试镜像客户端 |
| **公会 NPC 对话分支复杂化**(4 职业 × 多状态) | 低 | 简单 if-else 链,不做 DSL;4 职业 × 2 状态 = 8 分支 |
| **TierUnlockModal 在战斗过渡时被关** | 低 | modal 状态在 store 派生,phase 切换不重置;下次 idle 自动重开 |
| **多人房间 EXP 共享语义** | 中 | **v0.5 排除**:multiplayer_room 走独立 EXP 规则,留 v0.6 |
| **属性点 × 职业节点 attribute_mod 总和可能 > 20** | 低 | 客户端在分配按钮处显示"将达到 STR 21,超出钳制范围"提示;服务端钳制到 20 |
