# v0.5 — Level / EXP & Class System Design

**Date:** 2026-06-06
**Branch:** `v0.5-dev`
**Status:** Approved design (brainstorm §1–§6 all confirmed by user)
**Supersedes:** v0.4 (combat mechanics preserved; new growth loop added on top)

---

## 0. Summary

v0.5 brings the **character growth loop** to OpenTaleRunner:

- **Level-EXP** — players gain EXP from combat results and narrative action
  submissions, level up, and spend unallocated attribute points.
- **Class System** — players choose a class (warrior / cleric / mage / thief)
  at character creation **or** at any Adventurer's Guild. Each class has a
  4-tier × 3-pick-1 skill tree (12 nodes, 48 total across 4 classes).
- **Server-authoritative** — character data lives in a JSON blob inside the
  `characters` table; v0.5 adds fields to the Pydantic model and a strict
  validator. No DB migration needed.

Three milestones: **v0.5.1 Level-EXP → v0.5.2 Class → v0.5.3 Guild**.

### 1.3 Out of scope for v0.5 (v0.6+)

- Class re-spec / multi-class / hybrid classes
- Guild dynamic generation (storybook pre-places 1; generator deferred)
- Skill level / skill experience (binary "learned / not learned" only)
- Quest / discovery / exploration EXP (explicitly excluded this round)
- Cross-character / cross-account shared skill trees
- Skill animation / in-combat "learned skill QTE" (skill action stays
  hidden until v0.6 re-introduces SkillRegistry)

### 1.4 Dependencies & conflict points

- Existing `updateAttributes` clamps to `[3, 18]`; v0.5 must widen to
  `[1, 20]`. Old saves migrated with `_migrate_v04_to_v05` (idempotent).
- v0.4 combat has 4 difficulty tiers; EXP must scale with them to prevent
  easy-mode grinding (Easy ×0.5, Normal ×1, Hard ×1.5, Deadly ×2).
- Server is authoritative on `level / exp / expToNext`; client grant is
  trusted but the server always re-derives `expToNext` from `level` on
  PATCH.

## 2. Data Model

### 2.1 Character new fields (client + server symmetric)

```typescript
// client/src/types/character.ts (additive)
export interface Character {
  // ... existing fields preserved ...
  level: number;                       // [1, 20], default 1
  exp: number;                         // current EXP towards next level
  expToNext: number;                   // server-emitted (avoid client drift)
  unspentAttributePoints: number;      // 0-20, free allocation pool
  classId: string | null;              // null = classless
  classSkills: ClassSkillNode[];       // unlocked nodes (unique by classId+nodeId)
}

export interface ClassSkillNode {
  classId: string;          // denormalized for fast class filter
  nodeId: string;           // e.g. 'warrior_t1_2'
  unlockedAt: number;       // worldDay for timeline
}
```

```python
# server/models/character.py (additive)
class ClassSkillNode(BaseModel):
    classId: str
    nodeId: str
    unlockedAt: int


class CharacterResponse(BaseModel):

    level: int = 1
    exp: int = 0
    expToNext: int = 100            # server-authoritative

### 2.3 ClassRegistry aggregation

```

v0.5.2 starts with 4 classes. Future classes only need a new TS file + one

### 2.4 Pending-tier-choice derivation

"Does the player need to pick a T2/T3/T4 node?" is a **pure derivation** —
no flag stored, no race conditions:

```typescript
// client/src/services/class/classService.ts
export function pendingTierChoice(character: Character): 2 | 3 | 4 | null {
  if (!character.classId) return null;
  const TIER_UNLOCK: Record<2|3|4, number> = { 2: 5, 3: 10, 4: 15 };
  const def = getClass(character.classId);
  if (!def) return null;
  for (const tier of [2, 3, 4] as const) {
    if (character.level >= TIER_UNLOCK[tier]) {
      const has = character.classSkills.some(n =>
        def.nodes.find(d => d.id === n.nodeId)?.tier === tier
      );
      if (!has) return tier;
    }
  }
  return null;
}
```

T1 is written into `classSkills` at the moment the class is chosen
(no modal needed for the first pick).

### 2.5 Server-authoritative fields

- `level` / `exp` / `unspentAttributePoints` / `classId` / `classSkills` are
  written via `PATCH /api/v1/characters/{id}/...` with strict validation.
- Server always re-derives `expToNext = round(100 * level^1.5)` and writes
  it back (no client drift).
- `level` is bounded to [1, 20]. `classSkills` length is bounded to
  `min(floor(level/5) + 1, 4)` (L1=1, L5=2, L10=3, L15=4, L20=4).
- Attribute clamp widened from `[3, 18]` to `[1, 20]`.

### 2.6 Fields explicitly **not** stored

- Skill exp / skill level (binary only)
- Tier offset (T1-T4 fixed to L1/L5/L10/L15)
- Sub-class / hybrid class metadata
- Class rank (class is just `classId`)

## 3. Level-EXP Service

### 3.1 Level formula

```typescript
// client/src/services/level/expFormula.ts
export const MAX_LEVEL = 20;
export const EXP_PER_LEVEL_BASE = 100;

export function expToNext(level: number): number {
  if (level >= MAX_LEVEL) return Infinity;     // L20 cap, UI grayed
  return Math.round(100 * Math.pow(level, 1.5));
}

// Reference table
// L1→2:100  L2→3:283  L3→4:520  L4→5:800   L5→6:1122
// L6→7:1487 L7→8:1890 L8→9:2331 L9→10:2810 L10→11:3324
// L11→12:3873 L12→13:4457 L13→14:5074 L14→15:5724
// L15→16:6407 L16→17:7123 L17→18:7870 L18→19:8650
// L19→20:9462
// L1→20 cumulative ≈ 81 800 EXP
```

Server-side `server/services/exp_formula.py` mirrors the same formula;
**server is authoritative**.

### 3.2 EXP sources

| Source | Trigger | Base EXP | Difficulty mult | Hook point |
|---|---|---|---|---|
| **Combat hit** | `ActionResolver` hit lands | 5 | ✓ | emit `combat.hit` after resolveAttack |
| **Combat kill** | target HP → 0 | 20 | ✓ | emit `combat.kill` in applyDamage |
| **Combat victory** | `allEnemiesDead` | 30 | ✓ | emit `combat.end` ('victory') |
| **Combat defeat** | `allPlayersDead` | 10 | ✓ | emit `combat.end` ('defeat') — consolation |
| **Combat flee** | `beginResolving('fled')` | 0 | — | not granted |
| **Narrative submit** | `useActionSubmit` success | 2 | — | after narrative received |

Difficulty multiplier (read `currentDifficulty`):

```typescript
const DIFFICULTY_MULT: Record<Difficulty, number> = {
  easy: 0.5, normal: 1.0, hard: 1.5, deadly: 2.0,
};
// final = floor(base * mult)
```

### 3.3 grantExp — pure function

```typescript
// client/src/services/level/grantExp.ts
export interface GrantExpResult {
  character: Character;
  leveledUpTo: number[];   // triggered levels (multi-level possible)
  totalAwarded: number;    // actually consumed (capped at MAX_LEVEL)
}

export function grantExp(character: Character, amount: number,
                         difficulty: Difficulty): GrantExpResult {
  if (character.level >= MAX_LEVEL || amount <= 0) {
    return { character, leveledUpTo: [], totalAwarded: 0 };
  }
  const final = Math.floor(amount * DIFFICULTY_MULT[difficulty]);
  let { level, exp } = character;
  let pool = exp + final;
  let consumed = 0;
  const leveledUpTo: number[] = [];
  while (level < MAX_LEVEL) {
    const need = expToNext(level);
    if (pool < need) break;
    pool -= need;
    consumed += need;
    level += 1;
    leveledUpTo.push(level);
  }
  if (level >= MAX_LEVEL) pool = 0;

  // attribute points sync
  const unspentAttributePoints =
    character.unspentAttributePoints + leveledUpTo.length;

  return {
    character: { ...character, level, exp: pool, unspentAttributePoints },
    leveledUpTo,
    totalAwarded: consumed,
  };
}
```

**Invariants:**
- `level` is monotonically non-decreasing (only +1 on level up)
- `exp < expToNext(level)` (cap to 0 at MAX_LEVEL)
- A single grantExp may chain multiple level-ups; each grants +1
  unspentAttributePoint
- UnspentAttributePoints cap is implicit (MAX_LEVEL=20 → max 19 grants)

### 3.4 Attribute point spend

```typescript
characterStore.spendAttributePoint(attr: AttributeName)
  → updateAttributes({ [attr]: current[attr] + 1 })
  → unspentAttributePoints -= 1
  → PATCH /api/v1/characters/{id}/attributes/spend
```

**Attribute range [1, 20]**, enforced on both client and server. L20 can
still spend previously stored points but `grantExp` will not issue new ones.

### 3.5 EventBus hook integration

| System | Location | Event |
|---|---|---|
| **ActionResolver** | hit / kill end | emit `combat.hit` / `combat.kill` |
| **CombatView** | combat end branch | emit `combat.end` with outcome |
| **useActionSubmit** | narrative received | emit `narrative.submit` |
| **characterStore** | subscribes to all | `grantExp(...)` → set state |

**Event flow:**

```
ActionResolver  ──emit──>  EventBus  ──subscribe──>  characterStore
useActionSubmit ──emit──>    "           "          characterStore
CombatView     ──emit──>    "           "          characterStore
```

EventBus is used (not direct calls) because `grantExp` needs
`currentDifficulty` (global) + writes characterStore; decoupling allows
test mock at the event boundary.

### 3.6 Persistence timing

- Any characterStore write of `level / exp / unspentPoints` → debounce
  500ms → `PATCH /api/v1/characters/{id}` full body
- **Level-up moment** flushes immediately (must not be lost)
- 3 retries with exponential backoff on failure; on full failure, persist
  to `localStorage` as a fallback
- Server 422 → client rolls back + forces reload (drift defense)

### 3.8 Error handling

| Scenario | Behavior |
|---|---|
| Client formula vs server mismatch | server overwrites `level / exp / expToNext`; warn log |
| EXP overflow (concurrent grant) | store serializes via zustand middleware `subscribeWithSelector` + single reducer |
| MAX_LEVEL grant | discard amount, debug log |
| Server rejects (e.g. level > 20) | 422 → client forces reload |
| Old save import (no level/exp) | `_migrate_v04_to_v05` fills defaults |

| Layer | Cases |

### 4.2 ClassEffectAggregator (core pure function)

```typescript
// client/src/services/class/classEffects.ts
export interface ClassBonus {
  attributeMods: Partial<Attributes>;     // { STR: 2, CON: 1, ... }
  hpMaxBonus: number;
  mpMaxBonus: number;
  dodgeThresholdBonus: number;           // accumulated, negative lowers threshold
  damageModifier: number;                // +0.1 + 0.15 = 0.25
  expBonus: number;                      // accumulated
  qteToleranceMs: number;
}

export const EMPTY_CLASS_BONUS: ClassBonus = {
  attributeMods: {}, hpMaxBonus: 0, mpMaxBonus: 0,
  dodgeThresholdBonus: 0, damageModifier: 0, expBonus: 0, qteToleranceMs: 0,
};

export function aggregateClassEffects(character: Character): ClassBonus {
  if (!character.classId) return EMPTY_CLASS_BONUS;
  const def = getClass(character.classId);
  if (!def) return EMPTY_CLASS_BONUS;
  const bonus: ClassBonus = { ...EMPTY_CLASS_BONUS };
  for (const node of character.classSkills) {
    const def2 = def.nodes.find(n => n.id === node.nodeId);
    if (!def2) continue;  // defensive: skip invalid
    applyEffect(bonus, def2.effect);
  }
  return bonus;
}
```

**Injection points** (subscribers / direct calls):

| Location | Injection |
|---|---|
| `attributes` calc | `finalAttr = character.attributes + bonus.attributeMods` |
| `maxHp` calc | `finalMaxHp = character.maxHp + bonus.hpMaxBonus` |
| `maxMp` calc | `finalMaxMp = character.maxMp + bonus.mpMaxBonus` |
| combat damage | `finalDmg = baseDmg * (1 + bonus.damageModifier)` |
| hit threshold | `finalThreshold = threshold - bonus.dodgeThresholdBonus` |
| EXP | `finalExp = baseExp * (1 + bonus.expBonus)` |
| QTE window | `finalWindowMs = baseWindowMs + bonus.qteToleranceMs` |

**ClassBonus is a derived value, never written back to `character` state**
to avoid dual-source-of-truth bugs.

### 4.6 Server validation (v0.5.2)

```python
# server/services/class_validator.py
ALLOWED_CLASSES = {'warrior', 'cleric', 'mage', 'thief'}
NODE_ID_RE = re.compile(r'^(warrior|cleric|mage|thief)_t[1-4]_[1-3]$')


def _expected_node_count(level: int) -> int:
    """L1=1, L5=2, L10=3, L15=4, L20=4 (capped)"""
    if level < 5: return 1
    if level < 10: return 2
    if level < 15: return 3
    return 4


def validate_class_update(char: dict, new_class_id: str | None,
                          new_class_skills: list[dict]) -> None:
    if new_class_id is not None and new_class_id not in ALLOWED_CLASSES:
        raise HTTPException(422, f"invalid classId: {new_class_id}")

    expected = _expected_node_count(char.get("level", 1))
    if len(new_class_skills) > expected:
        raise HTTPException(422,
            f"too many class skills ({len(new_class_skills)} > {expected})")

    for node in new_class_skills:
        nid = node.get("nodeId", "")
        if not NODE_ID_RE.match(nid):
            raise HTTPException(422, f"invalid nodeId format: {nid}")
        if node.get("classId") != new_class_id:
            raise HTTPException(422, f"node classId mismatch")

    current = char.get("classId")
    if current is not None and current != new_class_id:
        raise HTTPException(422, "classId is locked in v0.5 (cannot change class)")

    if new_class_id is not None and len(new_class_skills) == 0:
        raise HTTPException(422, "must have at least T1 node when choosing class")
```

**Server does NOT validate effect fields** — that is the client's
responsibility. Server validates: classId allowlist, node count limit,
nodeId format, classId lock.

def _migrate_v04_to_v05(data: dict) -> dict:
    """Idempotent backfill on every create/update."""
    data.setdefault("level", 1)
    data.setdefault("exp", 0)
    data.setdefault("expToNext", 100)

    return data

### 5.4 New routes

```python
# server/routers/character_router.py (additions)
from services.class_validator import validate_class_update
from services.exp_formula import exp_to_next, MAX_LEVEL


@router.patch("/{char_id}/exp")
async def grant_exp(char_id: str, body: ExpGrantRequest,
                    repo=Depends(get_character_repo),
                    player_id=Depends(get_current_player)):
    """Server-authoritative EXP grant."""
    char = await repo.get(char_id)
    if not char:
        raise HTTPException(404, "Character not found")
    if char.get("playerId") != player_id:
        raise HTTPException(403, "Not your character")

    new_level, new_exp = apply_exp_formula(
        char["level"], char["exp"], body.amount, body.difficulty
    )
    attr_points = char.get("unspentAttributePoints", 0) + (
        max(0, new_level - char["level"])
    )
    patch = {
        "level": new_level,
        "exp": new_exp,
        "expToNext": exp_to_next(new_level),
        "unspentAttributePoints": attr_points,
    }
    await repo.update(char_id, {**char, **patch})
    return patch


@router.patch("/{char_id}/class")
async def set_class(char_id: str, body: ClassSetRequest,
                    repo=Depends(get_character_repo),
                    player_id=Depends(get_current_player)):
    """Class selection (creation wizard or guild)."""
    char = await repo.get(char_id)
    if not char:
        raise HTTPException(404, "Character not found")
    if char.get("playerId") != player_id:
        raise HTTPException(403, "Not your character")

    validate_class_update(char, body.classId, body.classSkills)
    patch = {"classId": body.classId, "classSkills": body.classSkills}
    await repo.update(char_id, {**char, **patch})
    return patch


@router.patch("/{char_id}/attributes/spend")
async def spend_attribute_point(char_id: str, body: AttributeSpendRequest,
                                 repo=Depends(get_character_repo),
                                 player_id=Depends(get_current_player)):
    """+1 attribute from unspent pool."""
    char = await repo.get(char_id)
    if not char:
        raise HTTPException(404, "Character not found")
    if char.get("playerId") != player_id:
        raise HTTPException(403, "Not your character")
    if char.get("unspentAttributePoints", 0) <= 0:
        raise HTTPException(400, "no unspent points")
    if body.attribute not in ("STR", "DEX", "CON", "INT", "WIS", "CHA"):
        raise HTTPException(400, "invalid attribute")
    attrs = char.get("attributes", {})
    new_val = min(20, attrs.get(body.attribute, 10) + 1)
    attrs[body.attribute] = new_val
    await repo.update(char_id, {
        **char,
        "attributes": attrs,
        "unspentAttributePoints": char["unspentAttributePoints"] - 1,
    })
    return {
        "attributes": attrs,
        "unspentAttributePoints": char["unspentAttributePoints"] - 1,
    }
```

### 5.5 Server formula mirror

```python
# server/services/exp_formula.py
MAX_LEVEL = 20


def exp_to_next(level: int) -> int:
    if level >= MAX_LEVEL:
        return 0  # client uses Infinity; server uses 0
    return round(100 * (level ** 1.5))


def apply_exp_formula(level: int, exp: int, amount: int,
                      difficulty: str = 'normal') -> tuple[int, int]:
    """Mirror of client grantExp logic. Returns (new_level, new_exp)."""
    mult = {'easy': 0.5, 'normal': 1.0, 'hard': 1.5, 'deadly': 2.0}.get(difficulty, 1.0)
    final = int(amount * mult)
    if level >= MAX_LEVEL or final <= 0:
        return (level, exp)

    pool = exp + final
    while level < MAX_LEVEL:
        need = exp_to_next(level)
        if pool < need:
            break
        pool -= need
        level += 1
    if level >= MAX_LEVEL:
        pool = 0
    return (level, pool)
```
