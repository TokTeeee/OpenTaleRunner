# v0.6.4 属性分配功能

## 背景

`Character.unspentAttributePoints` 字段已存在，`grantExp` 升级时自动 +1。LevelBar 提示"点击下方 +1 按钮"但按钮不存在，`characterStore` 缺少 `allocateAttribute` action。

## 目标

实现升级后属性分配的完整交互：行内 +1/-1 预览 + 确认/重置。

## 设计

### 1. characterStore 新增 `allocateAttribute` action

```typescript
allocateAttribute: (attrs: Partial<Attributes>) => void;
```

- 接收一个 `Partial<Attributes>`，如 `{ STR: 2, INT: 1 }` 表示本次分配 STR+2、INT+1
- 校验：分配总数 ≤ `unspentAttributePoints`，每个属性增加值 ≥ 0
- 执行：累加到 `character.attributes`，扣减 `unspentAttributePoints`
- 校验失败静默返回原 state（防御性编程）

### 2. CharacterPanel 属性行内 +1/-1 预览

当 `unspentAttributePoints > 0` 时，属性网格进入"分配模式"：

- 每个属性行右侧出现 **+1** 按钮
- 点击 +1 后：该属性预览值 +1（黄色高亮），剩余点数 -1
- 已分配的属性行出现 **-1** 按钮，可撤回单点分配
- 属性网格下方出现操作栏：**确认分配** / **重置**

预览状态由组件内 `useState` 管理（`pending: Partial<Attributes>`），不写入 store。

### 3. 确认 / 重置

- **确认**：调用 `allocateAttribute(pending)`，清空 pending state
- **重置**：清空 pending state，所有预览值恢复

### 4. 交互细节

- +1 按钮仅当剩余可分配点数 > 0 时可点击
- -1 按钮仅当该属性 pending 值 > 0 时可点击
- 确认按钮仅当有 pending 分配（至少 1 点）时可点击
- 属性值显示格式：基础值 + 预览增量（如 `8 → 9` 或 `8+1`）
- 分配模式结束后（unspentAttributePoints === 0），按钮和操作栏自动消失

### 5. 服务端同步

`allocateAttribute` 为本地 store 操作。属性变更需同步到服务端：
- 在 `allocateAttribute` action 内，执行 PATCH 请求同步 `attributes` 和 `unspentAttributePoints`
- 复用现有的 `subscribeCharacterEvents` 中的 API 调用模式

### 6. 文件改动

| 文件 | 改动 |
|------|------|
| `client/src/stores/characterStore.ts` | 新增 `allocateAttribute` action |
| `client/src/components/panels/CharacterPanel.tsx` | 属性行 +1/-1 按钮 + 确认/重置栏 |
| `client/tests/stores/characterStore-allocate.test.ts` | allocateAttribute 单测 |

### 7. 不做的事

- 不做属性上限检查（当前无属性上限定义，YAGNI）
- 不做属性减少/重分配（只增不减）
- 不做动画效果
- 不做属性加点音效
