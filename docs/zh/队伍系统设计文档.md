# 队伍系统详细设计文档

> 队伍系统是影响游戏性最大的新增系统。玩家可以组建冒险队伍，成员包括 NPC、幽灵 NPC（其他玩家化身）、动物/宠物、甚至被驯服的怪物。队伍在战斗、探索、社交中提供协助，GM 在各系统执行时联动队伍能力。

---

## 一、队伍数据模型

### 1.1 PartyMember 类型

```typescript
type MemberType = 'npc' | 'ghost_npc' | 'animal' | 'monster';
type MemberRole = 'combat' | 'support' | 'scout' | 'utility';

interface PartyMember {
  /** 队伍内唯一 ID */
  memberId: string;

  /** 成员类型 */
  memberType: MemberType;

  /** 来源 ID（npcId / ghostNpcId / 临时生成的 ID） */
  sourceId: string;

  /** 显示名称 */
  name: string;

  /** 称谓/类型标签 */
  label: string;

  /** 外观描述 */
  appearance: string;

  /** 性格/行为特征 */
  personality: string;

  /** 在队伍中的角色定位 */
  role: MemberRole;

  /** 属性（STR/DEX/CON/INT/WIS/CHA） */
  attributes: Record<string, number>;

  /** 技能列表 */
  skills: Array<{
    name: string;
    level: number;
    description: string;
    relatedAttribute: string;
  }>;

  /** 当前状态 */
  status: {
    hp: number;
    maxHp: number;
    isConscious: boolean;
    conditions: string[];
  };

  /** 职业/战斗能力 */
  combatAbilities: CombatAbility[];

  /** 辅助能力（非战斗） */
  utilityAbilities: UtilityAbility[];

  /** 加入时间 */
  joinedAt: string;

  /** 加入原因 */
  joinReason: string;

  /** 与玩家的关系描述 */
  relationshipDescription: string;

  /** 忠诚度（0-100，影响是否离队） */
  loyalty: number;

  /** 离队条件 */
  leaveConditions: LeaveCondition[];

  /** 特有对话/互动 */
  personalityTraits: string[];

  /** 是否可以升级 */
  canLevelUp: boolean;

  /** 队伍经验值 */
  experience: number;
}
```

### 1.2 战斗能力 & 辅助能力

```typescript
interface CombatAbility {
  name: string;
  type: 'attack' | 'defend' | 'heal' | 'buff' | 'debuff' | 'taunt';
  description: string;
  /** 对判定系统的加成 */
  bonus: {
    type: 'damage_bonus' | 'defense_bonus' | 'skill_bonus' | 'elemental_damage';
    value: number;
    condition?: string;  // 触发条件描述
  };
  /** 冷却时间（战斗回合数） */
  cooldown: number;
}

interface UtilityAbility {
  name: string;
  type: 'lockpick' | 'track' | 'negotiate' | 'craft' | 'heal_outside' | 'carry' | 'scout' | 'intimidate' | 'identify' | 'sneak';
  description: string;
  /** 能力等级 1-10 */
  level: number;
  /** 对判定系统的加成 */
  bonus: number;
}
```

## 三、招募系统

### 3.1 NPC 招募条件

GM 通过 `consequences` 结构返回招募结果。客户端检查条件后执行：

```typescript
interface RecruitCheck {
  /** 目标 ID */
  targetId: string;

  /** 目标类型 */
  targetType: MemberType;

  /** 检查条件 */
  conditions: RecruitCondition[];

  /** 全部满足时的招募结果 */
  onSuccess: PartyMember;

  /** 部分满足时的叙事 */
  partialNarrative: string;
}

interface RecruitCondition {
  type: 'relationship_level' | 'attitude' | 'reputation' | 'goal_match' | 'past_experience' | 'combat_victory' | 'skill_check';
  /** 条件值 */
  value: number | string;
  /** 是否满足 */
  met: boolean;
  /** 人类可读描述 */
  description: string;
}
```

### 3.2 各类成员的招募路径

| 成员类型 | 招募途径 | 条件 |
|---------|---------|------|
| **NPC（关系好）** | 好感度达标后 GM 叙事中提出 | 好感 ≥50 + 目标一致 + 声望不冲突 |
| **NPC（雇佣）** | 公会发布雇佣委托 | 支付金币 + 基础好感 10 |
| **幽灵 NPC** | 特殊偶遇事件后双方同意 | 完成一次交互 + 态度友善 |
| **动物** | 驯服检定（WIS 判定） | 判定成功 + 有食物 |
| **怪物（战败后）** | 击败后 CHA 说服 | 击败 + CHA 检定成功 + 声望暴力值不超阈值 |

### 3.3 招募流程

```
玩家行为 → GM 评估 → 叙事中包含招募提示
                         │
            ┌────────────┴────────────┐
            ▼                         ▼
    consequences.recruit = {     GM 叙事中暗示可以招募
      targetId,                  玩家主动输入 "[招募{name}]"
      targetType,                        │
      conditions,                        ▼
      memberData                 客户端检查条件
    }                                    │
    客户端自动检查条件            ┌──────┴──────┐
    → 全满足：自动加入            │ 满足  │ 不满足
    → 不满足：GM 叙事提示原因     ▼       ▼
                                 加入    GM告知原因
```

## 四、队伍在核心系统中的作用

### 4.1 战斗系统联动

`JudgmentSystem.evaluate()` 在计算判定时：

```typescript
function getPartyCombatBonus(context: ActionContext, party: PartyState): PartyCombatBonus {
  const bonus: PartyCombatBonus = {
    totalDamageBonus: 0,
    totalDefenseBonus: 0,
    totalSkillBonus: 0,
    memberActions: [],
  };

  for (const member of party.members) {
    if (!member.status.isConscious) continue;

    for (const ability of member.combatAbilities) {
      const relevant = isRelevantToAction(ability, context);
      if (!relevant) continue;

      switch (ability.bonus.type) {
        case 'damage_bonus':
          bonus.totalDamageBonus += ability.bonus.value;
          break;
        case 'defense_bonus':
          bonus.totalDefenseBonus += ability.bonus.value;
          break;
        case 'skill_bonus':
          bonus.totalSkillBonus += ability.bonus.value;
          break;
      }

      bonus.memberActions.push({
        memberId: member.memberId,
        memberName: member.name,
        abilityName: ability.name,
        effect: `${member.name}使用【${ability.name}】：${ability.description}（+${ability.bonus.value}）`,
      });
    }
  }

  return bonus;
}
```

判定结果中注入队伍贡献：

```
判定结果：成功
  2d6: [3,4] +2(属性) +1(技能) +3(装备) = 13 vs DC5
  [队伍]
  艾琳使用【精准刺击】：集中攻击弱点（+2）
  布洛克使用【盾墙】：格挡一次攻击（+1防御）
  → 最终：15 vs DC5 → 大成功
```

### 4.2 探索系统联动

`PromptBuilder` 中注入队伍能力提示：

```
【队伍可用能力】
- 艾琳（潜行者）：开锁 Lv.4 — 可以尝试打开上锁的门
- 灰爪（猎犬）：追踪 Lv.5 — 可以追踪气味踪迹
- 布洛克（战士）：负重 +50kg — 可以携带更多物品
```

GM 在生成选项时，如果场景涉及锁门/追踪/潜行，考虑生成"让艾琳撬锁"之类的选项。

### 4.3 社交系统联动

```
【队伍中的社交专家】
- 格罗姆（矮人商人）：谈判 Lv.3 — 交易时可能获得更好价格
- 赫卡特（术士）：威吓 Lv.4 — 可以用魔法震慑不友善的NPC
```

### 4.4 Prompt 注入结构

每次 GM 调用时，`buildCharacterLayer` 或新方法 `buildPartyLayer` 注入：

```

成员 1/4：艾琳·灰烬（佣兵）
  HP: 18/22 | 忠诚: 85/100

  辅助: 追踪 Lv.5, 警戒 Lv.3

- 如果面对锁住的门且有队员会撬锁 → 暗示"队员可以帮忙"
- 如果面对复杂谈判且有队员会交涉 → 暗示"队员可以代为交涉"
```

## 六、GM 交互接口

### 6.1 consequences 扩展

```typescript
interface ConsequenceData {
  // ... 现有字段 ...

  /** 队伍相关 */
  recruit?: {
    targetId: string;
    targetType: MemberType;
    targetName: string;
    memberData: PartyMember;
    conditions: Array<{
      type: string;
      description: string;
      met: boolean;
    }>;
    narrative: string;  // 招募场景的叙事
  };
  partyMemberUpdate?: {
    memberId: string;
    hpChange?: number;
    loyaltyChange?: number;
    conditionsAdded?: string[];
    conditionsRemoved?: string[];
    learnedAbility?: CombatAbility | UtilityAbility;
  };
  partyMemberLeave?: {
    memberId: string;
    reason: string;
    narrative: string;
  };
}
```

> `recruit / partyMemberUpdate / partyMemberLeave` 三个字段的类型定义存在于 `applyConsequences.ts` 的 `ConsequenceData` 接口，但**当前没有任何消费代码**（`applyConsequences` 的 switch 没有命中这些 case）。这意味着即使 GM 返回了 recruit 数据，客户端也不会自动 `addMember`——目前队员的加入完全依赖其他途径（手动 UI、debug 工具等）。
>
> P3.2 (`PartyRecruitChecker`) 即对应此修复。

### 6.2 GM 在叙事中影响队伍

GM 返回的叙事中插入队伍行动描述：

```
正常叙事：
"你推开了地下室的门..."

有队伍时：
"布洛克举盾护在你前方，推开了地下室厚重的铁门。艾琳迅速扫视了一圈黑暗的空间..."
```

GM 不需要特殊字段——只需在叙事中自然提及队员。`NPCIntroduced` 机制同样适用于新队员的加入。

### 6.3 队伍判定介入

`JudgmentSystem.evaluate()` 读取 `PartyStore`：

```typescript
// 判定时自动计算队伍加成
const partyBonus = usePartyStore.getState().getCombatBonus();
const totalEquipmentBonus = effectResult.totalEquipmentBonus + partyBonus.totalDamageBonus + partyBonus.totalDefenseBonus;
```

## 七、忠诚度系统

### 7.1 忠诚度变化

> 7.1 列出的 8 条"事件驱动忠诚度变化"映射表**当前未实现**。代码中只有 `updateMemberLoyalty(memberId, delta)` 让调用方传入数值变化，事件驱动的逻辑在 P3.3 中标记为待办。

忠诚度的数值变化由调用方通过 `updateMemberLoyalty` 主动增减，常见数据流：

| 来源 | 调用方式 |
|------|----------|
| `applyConsequences` 根据 GM 返回调整 | `updateMemberLoyalty(memberId, delta)` |
| 招募时初始化 | `addMember` 时设置初始值 |
| UI 操作 | 队员详情弹窗"解雇 / 表扬"按钮 |

### 7.2 忠诚度阈值

> 5 档阈值（80/50/20/10）在 7.2 表中描述的"行为影响"（拒绝命令、必定离队等）**当前未实现**。`LeaveCheck` 任务 P3.4 也未落地。`leaveConditions` 字段在 PartyMember 类型中存在，但 `partyStore` 不做自动触发——离队需通过外部 `removeMember` 调用。

当前实际行为：忠诚度仅作为查询字段，离队由外部逻辑（剧情触发、玩家主动解雇）显式执行。

## 九、API 与服务端

### 9.1 consequences 传输

GM 返回的 JSON 已包含 recruit/partyMemberUpdate/partyMemberLeave 字段。服务端不需要额外存储队伍数据（队伍是客户端本地概念），但 NPC 关系变化会上传。

### 9.2 可选：服务端队伍快照

```sql
-- 可选：存储玩家的队伍快照到服务端
ALTER TABLE characters ADD COLUMN party_snapshot TEXT DEFAULT '{}';
-- JSON: { members: [...], updatedAt: "..." }
```

客户端定期上传（与编年史同步时），用于：
- 其他玩家通过幽灵 NPC 看到"这个人有一个冒险队伍"
- 防数据丢失

## 十一、规划

期望将队伍数据模型与状态管理层彻底打通，让每位队员的战斗能力与辅助技艺无缝注入判定系统，使队伍贡献在每一次骰子检定中可见、可感。GM 在叙事中自然提及队员行动，Prompt 层智能感知场景需求，主动提示可调用的队员能力。

期待招募系统成为世界叙事的一部分——玩家通过好感积累、公会雇佣、特殊偶遇或战败驯服等多样途径招揽伙伴，每一种途径都有其独特的叙事氛围与检定挑战。忠诚度随冒险起伏变化，真正影响队员的去留决心。

希望打造直观而丰富的队伍管理界面：队员卡片一眼可见忠诚与状态，详情弹窗展示深度角色数据，能力总览随时提醒玩家队伍整体的战斗力与辅助潜力。

期待队伍系统向更深层演进——队员随冒险积累经验与成长，动物与怪物通过专门驯服检定加入队伍，幽灵 NPC 入队拥有特殊的双向同意机制。服务端快照确保队伍数据永不丢失，负重系统则影响旅行节奏与策略选择，让每一次出征都需权衡人力与物资。
