# 角色系统

> 角色是玩家在艾瑟兰世界中的化身。本文档描述角色的数据模型、属性体系、技能机制、状态系统、名誉系统以及角色创建流程。

---

## 一、介绍

角色系统是游戏的核心数据容器。每个角色拥有六维属性、动态技能列表、HP 与精力状态、名誉值、条件状态和物品背包。角色数据通过 Zustand `characterStore` 管理，持久化到服务端 `/api/v1/characters` 实现跨设备同步。

角色通过六步创建向导生成：从选择出生村庄到初始装备分配，全程由 PM 引擎引导叙事，确保每个角色都有独特的出身背景。

> **v0.5.1 新增** — 角色现在拥有 `level` / `exp` / `expToNext` /
> `unspentAttributePoints` 四个等级-经验字段，以及 `classId` / `classSkills`
> 两个职业字段（v0.5.2 起启用）。升级公式为
> `expToNext(L) = round(100 * L^1.5)`，上限 20 级。详见 CHANGELOG v0.5.1。
>
> **v0.5.2 新增** — 4 基础职业（战士/牧师/法师/盗贼），每职业 4 tier × 3 选 1
> 技能树（48 节点）。Tier 解锁：T1 选职业时立即获得，T2 L5、T3 L10、T4 L15。
> 7 类被动效果：`attribute_mod` / `hp_max_bonus` / `mp_max_bonus` /
> `dodge_threshold_bonus` / `damage_modifier` / `exp_bonus` / `qte_tolerance`。
> 角色创建 Step 7 选职业，详见 CHANGELOG v0.5.2 与
> [v0.5 等级与职业设计 spec](../../superpowers/specs/2026-06-06-v0.5-level-class-design.md)。
>
> **v0.5.3 新增** — 故事书预置 **冒险者公会·光辉城总部**（POI
> `adventurer_guild_1` + NPC `guild_class_officer_alden` 公会主事·奥尔登）。
> 新组件 `GuildClassModal`（`classId=null` 时进入公会弹出，4 职业 → T1 二步选）
> 与 `TierUnlockModal`（达到 L5/L10/L15 自动弹出 T2/T3/T4 三选一，战斗中隐藏）。
> `characterStore` 加 `setClass(classId, classSkills)` 本地优先 mutator。
> 详见 CHANGELOG v0.5.3。

## 二、设计

### 2.1 数据模型

```
Character {
  playerId: string           // 玩家唯一标识
  name: string               // 角色名
  attributes: {              // 六维属性, 范围 1-20 (v0.5.1 放宽)
    STR: number  // 力量 — 影响物理判定
    DEX: number  // 敏捷 — 影响速度/躲避
    CON: number  // 体质 — 影响 HP/抗性
    INT: number  // 智力 — 影响知识/魔法
    WIS: number  // 感知 — 影响观察/直觉
    CHA: number  // 魅力 — 影响社交/NPC 态度
  }
  skills: Skill[]            // 技能列表
  hp: number                 // 当前生命值 (0~maxHp)
  maxHp: number              // 最大生命值
  reputation: Reputation     // 名誉系统
  inventory: Inventory       // 物品背包
  conditions: string[]       // 当前条件状态
  recentHistory: HistoryEntry[]  // 实际字段名是 recentHistory（不是 history），上限 10 条
  currentRegion: string
  currentSubRegion: string
  currentLocation: string
  currentCoordinates: { x, y, z }
  background: string         // 角色背景故事
  appearance: string         // 外貌描述
  joinedRegion: string       // 出身区域
}
```

每个 `Skill` 包含：`id`, `name`, `level` (1-10), `maxLevel`, `type` (`background` | `acquired`), `relatedAttribute`, `description`, `acquiredAt`, `experience`, `expToNext`。

### 2.2 characterStore API

Zustand store，支持 `getState()` 在 React 外部调用：

| 方法 | 签名 | 说明 |
|---|---|---|
| `setCharacter` | `(char: Character) => void` | 加载完整角色（初始化/加载存档） |
| `updateAttributes` | `(attrs: Partial<Attrs>) => void` | 更新属性，自动钳制到 [3, 18]（store 层就钳制，applyConsequences 路径与直接调用路径行为一致） |
| `updateIdentity` | `(changes) => void` | 修改角色名/外貌/背景 |
| `addCondition` | `(condition: string) => void` | 添加条件，触发 `condition.onAdded` hook |
| `removeCondition` | `(condition: string) => void` | 移除条件，触发 `condition.onRemoved` hook |
| `modifySkill` | `(skillId, {newName?, newDescription?, levelChange?}) => void` | 修改技能名称、描述或等级（`newDescription` 字段亦可用于编辑技能描述） |
| `addSkill` | `(skill: Skill) => void` | 学习新技能 |
| `updateHP` | `(hp: number) => void` | 更新 HP，钳制到 [0, maxHp] |
| `updateVital` | `(delta: Partial<Vital>) => void` | 更新精力值，钳制到 [0, 100] |
| `updateReputation` | `(delta) => void` | 应用名誉变化，钳制到 [-100, 100] |
| `updateInventory` | `(inv: Inventory) => void` | 替换整个物品栏 |
| `updateCurrency` | `(c: Partial<Currency>) => void` | 部分更新货币（`gold/silver/copper` 等） |
| `addHistory` | `(entry: HistoryEntry) => void` | 追加历史记录（保留最近 10 条） |
| `setLastActionTime` | `(time: string) => void` | 记录最后行动时间 |

### 2.3 六步创建向导

```
Step 1: 选择出生村庄
  └─ 从 12 个起始村庄中选择（皇家平原区域）

Step 2: PM 引导背景故事
  └─ GM(LLM) 根据选择的村庄生成角色出身叙事

Step 3: 属性分配
  └─ 基础 10 + 自由分配点数 → 六维属性 (3-18)

Step 4: 技能生成
  └─ GM 根据背景故事赋予初始技能 (type='background')

Step 5: 初始装备
  └─ GM 根据出身给予初始武器/护甲/物品

Step 6: 入世
  └─ 角色数据写入 characterStore + characterListStore
  └─ 上传到服务端 POST /api/v1/characters/create
  └─ 调用 PM 引擎生成首个场景
```

### 2.4 状态系统

**HP**: 当前生命值，范围 `[0, maxHp]`。通过 `updateHP()` 修改，钳制保证不越界。HP 归零不意味着永久死亡（v0.3），而是触发负面状态。

**精力 (Vital)**: 八项指标，范围 `[0, 100]`：

> `types/character.ts` 中 `VitalStats` 实际包含 **8 项**（thirst / wound / temperature / encumbrance 为新增 4 项）：

| 指标 | 说明 | 消耗方式 |
|---|---|---|
| `fatigue` | 疲劳度 | 行动 +5/次，战斗 +10/次，休息 -30/天 |
| `hunger` | 饥饿度 | 时间流逝 +3/小时，进食恢复 |
| `hygiene` | 卫生 | 探索/战斗 +2/次，城镇休息恢复 |
| `morale` | 士气 | 成功行动 +5，失败 -10，叙事事件调整 |
| `thirst` | 口渴 | 时间流逝 +4/小时，饮水恢复（比饥饿更快） |
| `wound` | 伤势 | 战斗/伤害 +N，休息/治疗 -N（与 HP 不同，叠加显示） |
| `temperature` | 体温 | 极端地形 ±N，过冷/过热触发条件 |
| `encumbrance` | 负重 | 拾取物品 +N（按重量），丢弃/存放 -N；>80 影响 travelSpeed |

**条件 (Conditions)**: 负面状态列表（中毒、受伤、骨折、诅咒等）。15 种预定义条件，支持模糊名称匹配。条件影响：
- `dicePenalty`: 判定骰子惩罚（取所有条件中的最大值）
- `travelSpeed`: 旅行速度倍率（取最小值）
- `regenMultiplier`: 恢复倍率（取最小值）
- 施加/移除时触发 `condition.onAdded` / `condition.onRemoved` 系统 Hook

### 2.5 名誉系统

| 字段 | 范围 | 说明 |
|---|---|---|
| `goodness` | -100 ~ 100 | 善良值（正面行为提升） |
| `violence` | 0 ~ 100 | 暴力值（战斗/杀戮累积） |
| `lawfulness` | -100 ~ 100 | 守法值（遵守 vs 打破规则） |
| `regional` | Record<string, number> | 各区域/派系的声望 |

PM 引擎在每次行动后根据叙事输出 `reputationChange`，`applyConsequences()` 分离全局键（goodness/violence/lawfulness/charisma）与区域键，分别写入 `characterStore`。

> `charisma` 在 `applyConsequences` 中不再被识别为全局键传入 `updateReputation`——`charisma` 现在被路由到 `attributes.CHA`（视为属性增量），与 `goodness`/`violence`/`lawfulness` 分离。其他键默认走 `regional`。

## 三、规划

期望引入等级-经验机制，让角色成长有明确的量化路径——每一次行动积累经验、每一次升级解锁自由属性点，成长曲线由玩家亲手塑造。同步完善 charisma 在名誉系统中的完整闭环，让社交魅力真正成为改变世界的隐形力量。

在此基础上，探索职业与转职系统，为角色赋予更丰富的扮演深度——从初始职业的选择到条件触发的华丽转职，每一次身份蜕变都伴随着全新技能与叙事可能。配合角色头像系统，让每一位冒险者都拥有独一无二的视觉身份。

远期期望开放血统与种族系统，引入非人种族选项与种族固有属性，让艾瑟兰大陆上的身份选择超越人类边界，开启真正多元的创角维度。

## 四、v0.4 增量

v0.4 在角色系统层面有三个交叉点：v0.4 Codex 图鉴把"角色"作为一个 6 分类之一 (player scope)，战斗系统接入 characterStore 的 HP/精力/状态字段，NPC 记忆系统按 `entityId='character:<id>'` 写入并召回。

### 4.1 Codex 图鉴中的角色 (player scope)

- v0.4 `codexStore` 的 6 分类包含 `player`，记录玩家在不同时间点的"里程碑快照"（如首次击败 BOSS / 首次进入隐藏区域 / 首次与某 NPC 缔结羁绊）
- 触发时机：`applyConsequences` 检测到 `reputationChange` 跨过门槛 / `conditionsAdded` 出现关键 condition 时调用 `codexSignature` 解锁
- 关键 commit: `c0664c6` codexStore, `e34676b` codexSignature, `e379a86` applyConsequences 触发

### 4.2 战斗系统对 characterStore 的访问

- v0.4 战斗时：`CombatEngine.startCombat({ party })` 复制 `character` HP / 精力 / 状态到 `combatStore.session.combatants`
- 战斗结束：`endCombat` 把 `combatants[i].hp / stamina / conditions` 写回 `characterStore`
- 重要约束：战斗过程中**不直接写** `characterStore`，避免战斗 UI 与主视图双绑定问题
- 详见 [战斗系统](战斗系统.md) 五、v0.4 增量

### 4.3 跨会话 NPC 记忆 (角色参与度)

- 玩家行动触发的 `commitEpisode` 会把 `player: <npcsInvolved>` 的事件写入 `MemoryManager`，scope=`npc`, `entityId=npcId`
- 当玩家再次与该 NPC 互动时，`PromptBuilder.buildGmMemoryRetrievalSection` 会召回这些 npc-scope 记忆
- 关键 commit: `ba3fbe6` useActionSubmit 集成
- 详见 [PM 引擎与 Prompt 系统](PM引擎与Prompt系统.md) 四、v0.4 增量

## 五、v0.5.3 增量 — 冒险者公会 & Tier 自动解锁

v0.5.3 把 v0.5.2 的"创建时选职业"扩展为**"创建可延后，进入公会补选"** +
"达到 L5/L10/L15 自动弹窗要求选 tier 节点"。

### 5.1 故事书预置公会

`client/storybook.json` 的 `royal_plains` sub-region 加上：

```json
{
  "id": "adventurer_guild_1",
  "name": "冒险者公会·光辉城总部",
  "type": "guild",
  "npcId": "guild_class_officer_alden",
  "services": ["class_selection", "tier_unlock", "quest_board"]
}
```

配套 NPC `guild_class_officer_alden`（公会主事·奥尔登）— 来自
`client/npc_templates.json` 的 `guild_class_officer` 模板（WIS 16 / INT 14，
技能 `[职业知识 L5 INT, 评估 L4 WIS]`，`canGrow: false`）。v0.6 计划加
`GuildGenerator` 按区域动态铺多公会。

### 5.2 GuildClassModal — 后置职业入口

触发条件：`open=true && character && character.classId === null`。
已有职业的玩家进入公会 → modal 隐藏，触发"欢迎回来"对话（v0.6 完善）。

两步流程：
1. 选职业（4 个按钮：warrior / cleric / mage / thief）
2. 选 T1 节点（该职业 T1 三个节点的简述 + 效果）

`setClass(pickingClass, [t1Node])` + `onClose()` **同步**先做，PATCH
`/api/v1/characters/{id}/class` 在 `void (async () => {...})()` 中跑（失败保留
本地状态，下次进公会重试）。

### 5.3 TierUnlockModal — 自动升级提示

读取 `pendingTierChoice(character)` 派生是否需要弹窗：

| 条件 | 结果 |
|---|---|
| `character === null` | 不弹 |
| `character.classId === null` | 不弹（玩家未选职业） |
| `isCombatActive({ phase })`（即 `phase === 'active' \|\| 'resolving'`） | 不弹（避免遮挡 QTE 提示） |
| `pendingTierChoice` 返回 `null` | 不弹（当前 tier 都已选或未到解锁等级） |
| `pendingTierChoice` 返回 `2 \| 3 \| 4` | 弹，列出该 tier 的 3 个节点 |

点节点 → `setClass(classId, [...classSkills, newSkill])` 同步追加 +
异步 PATCH /class。重渲染时 `pendingTierChoice` 看到该 tier 已有节点
→ 返回 `null` → modal 自动消失。

### 5.4 setClass mutator

`useCharacterStore.setClass(classId, classSkills)` 是本地优先的 setter —
先写 store 立刻让 UI 反应，再异步 PATCH 服务端。这与 `updateAttributes` /
`addSkill` 等的"本地立即更新"模式一致。

### 5.5 时序约束

- 公会 modal：玩家在战斗中走到公会入口 → `onClose` 拒绝打开（spec §4.3.2）
- Tier modal：L5 升级在战斗进行中触发 → `pendingTierChoice` 仍返回 2，
  但 `TierUnlockModal` 内部用 `isCombatActive` 守卫，**战斗结束
  (`phase='settled'`) 后才显示**。这样不会打断既有交互流。
