## 一、客户端架构

### 分层设计

```
┌─────────────────────────────────────────────────┐
│ UI 层 (components/)                              │
│   App.tsx, InteractionArea, panels, modals       │
├─────────────────────────────────────────────────┤
│ Hooks 层 (hooks/)                                │
│   usePMEngine, useAutoPlay, useVoiceInput        │
├─────────────────────────────────────────────────┤
│ Stores 层 (stores/)          Zustand + persist   │
│   gameStore, characterStore, worldStore,         │
│   settingsStore, multiplayerStore, partyStore ...│
├─────────────────────────────────────────────────┤
│ Services 层 (services/)    无状态 / 纯逻辑       │
│   engine/PMEngine, judgment/, sync/,             │
│   tts/, image/, crypto/, event/, activity/       │
├─────────────────────────────────────────────────┤
│ LLM / TTS / Image APIs (直接从客户端调用)       │
│   DeepSeek / OpenAI / MiMo / Anthropic / Edge    │
└─────────────────────────────────────────────────┘
```

### 关键设计决策

| 决策 | 说明 |
|---|---|
| **客户端 AI** | 服务端不运行游戏 LLM，所有 AI（PM 叙事、NPC 对话、AutoPlay）在客户端用用户 API Key 运行 |
| **服务端纯数据** | FastAPI 提供 REST API：世界状态、角色存档、编年史、NPC 注册、多人房间协调 |
| **Action 统一管线** | 无论手动/语音/AutoPlay，所有 Action 走 `usePMEngine.submitAction()` → 判定 → PM 请求 → 后果应用 → 存档 |
| **Zustand 持久化** | settingsStore 加密持久化到 localStorage（AES-256-GCM），API Key 不在明文中落盘 |
| **事件总线** | 14 个事件类型，组件间松耦合通信（SCENE_LOADED, DICE_ROLLED, NARRATIVE_RECEIVED 等） |

### 安全特性

| 特性 | 实现 | 文件 |
|---|---|---|
| API Key 加密存储 | AES-256-GCM + PBKDF2 + 设备唯一种子 | `services/crypto/CryptoService.ts` |
| Prompt 注入防护 | **18 种** regex 模式脱敏（`###`, ````json`, `<system>`, `<user>`, `<human>`, `<ai>`, `ignore previous instructions` 等, 见安全系统.md 2.2） | `services/security/sanitize.ts` |
| XSS 输出过滤 | DOMPurify，白名单标签（b/i/em/strong/br/p/ul/ol/li/span） | `services/security/sanitize.ts` |
| 调试日志 | 12 分类（GM/HTTP/TOOL/PM/TTS…），IndexedDB 持久化，浏览器 Console API | `services/logging/` |

### 分层架构

```
Router (薄层，仅处理HTTP请求)
    │  解析请求 → 调用Service → 返回JSON
    ▼
Service (业务逻辑层)
    │  依赖Repository接口，不依赖具体数据库
    ▼
Repository (数据访问接口+实现)
    │  SqliteXxxRepo → 未来可替换为 PostgresXxxRepo
    ▼
Database (连接管理)
       SQLite (当前) → PostgreSQL (未来扩展)
```

## 四、规划



### 客户端

在 AutoPlay 策略层面，期望从单一决策模型演进为多策略 AI 体系——冒险型、谨慎型、社交型等不同风格并存，使 AI 角色展现出更丰富的行为多样性。

实时同步方面，计划以 WebSocket 持久化连接替代当前 HTTP 轮询机制，将同步延迟降至亚秒级，为多人协作与即时事件响应奠定基础。

在前端体验上，将推进移动端响应式适配，使界面在触屏设备上拥有自然的交互手感；同时开启国际化之路，构建英文 UI 与多语言 Prompt 模板体系，降低非中文玩家的上手门槛。

### 服务端

存储层将迈向后端数据库的升级——从 SQLite 迁移至 PostgreSQL，以获得更高并发支持与更丰富的数据管理能力。同时引入 Redis 缓存层，为幽灵 NPC TTL 管理、热数据查询等高频访问场景提供低延迟响应。

服务端架构将走向无状态化与水平扩展：支持多 Worker 部署与负载均衡，使系统能够从容应对日益增长的玩家规模。编年史聚合将由定时轮训模式演进为消息队列驱动的事件模式，实现更即时、更精确的世界叙事生成。

LLM 能力的边界也将向服务端延伸——在客户端独立运行 AI 的基础上，服务端将逐步承担 NPC 自主行为的 LLM 增强，让世界中的 NPC 展现出更鲜活、更自洽的日常行为。

### 部署

运维基础设施将向生产级标准看齐：引入 Kubernetes Helm Chart 实现容器化编排；集成 Alembic 实现自动化数据库迁移，使版本迭代中的 Schema 变更安全可控；部署 Prometheus 指标采集与 Grafana 看板，建立全链路的健康检查与可观测体系。
