# 日志系统

> 双轨日志系统：客户端 12 分类调试日志器（IndexedDB 持久化）+ 服务端 Python RotatingFileHandler（请求中间件）。

---

## 一、介绍

客户端 `ClientLogger` 提供 12 个分类通道，支持 4 级日志、控制台彩色输出与内存缓冲；通过 `LogIndexedDB` 可选的持久化至浏览器本地数据库。服务端采用 Python `RotatingFileHandler` 标准日志体系，配合 FastAPI 中间件自动记录所有 HTTP 请求。

## 二、设计

### 2.1 客户端日志器

`services/logging/ClientLogger.ts`。12 个分类：

| 分类 | 说明 |
|------|------|
| `GM` | 游戏控制流程（Game Master） |
| `HTTP` | HTTP 请求/响应 |
| `TOOL` | LLM 工具调用 |
| `PM` | PM 引擎（剧情管理） |
| `STORE` | Zustand store 状态变更 |
| `TTS` | 语音合成 |
| `IMAGE` | 图片生成 |
| `GAME` | 游戏逻辑 |
| `MULTI` | 多人联机 |
| `SYNC` | 状态同步 |
| `SYSTEM` | 系统级事件 |
| `ERROR` | 全局错误捕获 |

4 个等级：`DEBUG(0)` / `INFO(1)` / `WARN(2)` / `ERROR(3)`。控制台输出带彩色前缀标记，内存缓冲区上限 200 条。

### 2.2 IndexedDB 持久化

`services/logging/LogIndexedDB.ts`。

- **数据库**：`AeslanLogs`，版本 v1
- **对象存储**：`entries`（keyPath=`id`，autoIncrement）
- **索引**：`timestamp`、`category`、`level`
- **自动清理**：当存储超过 `maxStorageMB`（默认 10MB）时，清除最旧 20% 的记录
- **开关**：由 `settingsStore.debug.persistToIndexedDB` 控制

> `LogIndexedDB` 已实现 `queryLogs(filters)` API，签名：`queryLogs({ startTime?, endTime?, categories?, levels?, searchText?, limit? })`，返回 `LogEntry[]`。`LoggerConfig` 字段也包含 `maxStorageMB`（默认 10），超过上限时按时间删除最旧 20%。

### 2.3 调试配置

`settingsStore.debug` 字段：

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | `boolean` | `false` | 总开关 |
| `logLevel` | `number` | `INFO(1)` | 最低记录等级 |
| `categories` | `string[]` | `["SYSTEM", "ERROR"]` | 启用的分类 |
| `persistToIndexedDB` | `boolean` | `false` | 是否写入 IndexedDB |
| `maxStorageMB` | `number` | `10` | IndexedDB 存储上限（MB），超出时按时间删除最旧 20% |

默认关闭调试，仅记录 `SYSTEM` 与 `ERROR` 分类，不持久化。

### 2.4 控制台 API

挂载于 `window` 的调试入口：

- `__aeslanDebug(true|false)` — 切换调试模式开关
- `__aeslanExportLogs('json'|'csv')` — 导出日志并触发浏览器下载
- `__aeslanClearLogs()` — 清空内存缓冲与 IndexedDB 所有记录

### 2.5 埋点位置

| 埋点 | 位置 |
|------|------|
| GM 请求/响应 | `useActionSubmit` |
| HTTP 耗时 | `HttpClient` |
| 场景生成 | `useSceneFlow` |
| PM 初始化 | `usePMInitialization` |

### 2.6 服务端日志

`server/logging_config.py`：基于 Python `logging` 标准库的 `RotatingFileHandler`（单文件 10MB，保留 7 个备份）。

环境变量：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SERVICE_LOG_ENABLED` | `true` | 是否启用日志 |
| `SERVICE_LOG_LEVEL` | `INFO` | 日志等级 |
| `SERVICE_LOG_DIR` | `server/logs/` | 日志目录（相对 `server/logging_config.py` 所在目录，即 `os.path.dirname(__file__) + "logs"`，不是工作目录的 `./logs`） |
| `SERVICE_LOG_FORMAT` | `text` | 输出格式（`text` 或 `json`） |
| `SERVICE_LOG_MAX_BYTES` | `10485760`（10 MB） | 单个日志文件大小上限，超限触发 `RotatingFileHandler` 轮转 |
| `SERVICE_LOG_BACKUP_COUNT` | `7` | 保留的历史日志文件数 |

8 个日志器：

| 日志器 | 用途 |
|--------|------|
| `api` | API 接口调用 |
| `db` | 数据库操作 |
| `npc` | NPC 相关逻辑 |
| `chronicle` | 编年史/世界状态 |
| `ghost` | 幽灵系统 |
| `dashboard` | 控制台面板 |
| `request` | HTTP 请求日志 |
| `llm` | LLM 调用日志 |

### 2.7 请求日志中间件

FastAPI `@app.middleware("http")` 全局中间件，记录每个请求的：方法、路径、状态码、耗时、客户端 IP。

### 2.8 相关系统

- **架构与配置**（`架构与配置.md`）：完整的 `settingsStore` 配置项定义
- **安全系统**（`安全系统.md`）：敏感信息（API Key、token）不写入日志，由过滤层在记录前截断

## 三、规划


期望在浏览器端提供按分类与等级灵活检索 IndexedDB 历史记录的日志过滤器，让开发者与玩家都能快速定位问题根因。服务端日志体系向结构化方向演进，支持 JSON 格式输出，为接入 ELK、Loki 等主流日志栈做好准备，实现日志的可视化聚合与实时监控告警。

进一步规划统一的远程日志上报能力，为客户端与服务端提供可配置的日志服务端点，实现集中化日志收集与分析，大幅降低分布式环境下的排障与运维成本。
