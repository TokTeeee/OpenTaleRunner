## 一、介绍

三大媒体子系统：TTS 文本转语音输出、Image 图片生成、STT 语音输入。每个子系统支持 3+ Provider，配置集中在 `settingsStore` 中统一管理，敏感字段通过 CryptoService 加密持久化。

## 二、TTS 语音输出

### 2.1 TTSClient API

构造函数 `new TTSClient(config?)`，从 `settingsStore.tts` 读取配置，支持可选的 voice/speed/provider 覆写（NPC 专用）。

| 方法 | 说明 |
|---|---|
| `speak(text)` | 异步播放完整文本。Edge 走 browser SpeechSynthesis，其他走 fetchTTS→decodeAudio→play |
| `speakStream(text)` | 按 CJK 标点（`。！？.!?`）分句后逐句 `fetchTTS` + `playSync`，实现逐句播放 |
| `generateAudioBlob(text)` | 返回到手音频 Blob，不播放 |
| `stop()` | 停止当前播放（AudioBufferSource + SpeechSynthesis） |

内部流程：`generateAudioBlob` → `fetchTTS`（调用 API 获取二进制）→ `decodeAudio`（Web Audio API 解码）→ `play`（异步）/ `playSync`（等待句结束）。

### 2.2 TTSQueue

FIFO 播放队列，串行逐条播放：

- `enqueue(text, onStart?, onEnd?)` — 入队，若空闲则自动开始播放
- `playNext()` — 取出队首播放，容错继续（catch 吞异常），保证队列不中断
- `clear()` — 清空队列并停止当前播放
- `isPlaying` — 只读播放状态

### 2.3 三 Provider

| Provider | 实现方式 | 备注 |
|---|---|---|
| **Edge** | `window.speechSynthesis` (Web Speech API) | 免费，无需 API Key，自动选中文语音 |
| **OpenAI** | POST `/v1/audio/speech`，返回 audio blob | 支持 voice/speed 参数 |
| **MiMo** | 统一 chat 端点，请求中带 `response_format: wav`，从响应中 base64 解码音频 | 走 `buildMimoTTSRequest` + `extractChatAudioBase64` |
| **Custom** | OpenAI 兼容路径，使用自定义 endpoint | 格式同 OpenAI TTS |

Edge 模式下 `speakStream` 退化为整体播放（不分句），因为 browser API 不支持逐句回调。

> MiMo 模式下 `speakStream` 也退化为整体播放（`TTSClient.ts:41` 中 `if (this.provider === 'edge' || this.usesMimoChatAPI)` 走 `speak()` 非分句路径），因为 MiMo 走 chat API 一次性请求整段文本，不支持单句 streaming。只有 OpenAI 和 Custom provider 走真正分句流式。

> Edge provider 实际走 `TTSClient.speakWithBrowser(text)` 三级回退链 (`TTSClient.ts:53`)：
> 1. 优先按 `lang='zh-CN'` 调用 `speechSynthesis.speak(new SpeechSynthesisUtterance(text))`
> 2. 失败/未配置 zh-CN 语音时回退 `lang='en-US'`
> 3. 都失败时退到 `getVoices()[0]`（任意可用语音），并打印 `console.warn`
> 
> `speakWithBrowser` 是 `private` 方法——外部应通过 `speak(text)` 或 `speakStream(text)` 走完整 client 流程。

### 2.4 NPC 语音池

`NPCVoiceManager.ts` — `assignVoiceToNPC(npcId)` 基于 DJB2 哈希确定性分配语音。

语音池 15 个 preset，循环使用 6 种 OpenAI voice（onyx / echo / fable / nova / shimmer / alloy），speed 范围 0.85–1.15，pitch 范围 0.8–1.15。返回 `NPCVoiceParams { voice_id, speed, pitch, provider: 'openai' }`。

配置开关 `npcIndependentVoice` 控制是否启用独立 NPC 语音。

### 2.5 配置

`TTSConfig { provider, apiKey, endpoint, model, voice, speed }`

| 配置项 | 默认值 |
|---|---|
| `provider` | `'openai'` |
| `endpoint` | OpenAI TTS 端点 |
| `model` | `'tts-1'` |
| `voice` | `'onyx'` |
| `speed` | `1.0` |
| `ttsEnabled` | `false` |
| `npcIndependentVoice` | `false` |

Provider 默认值从 `providerCatalog.getTTSProviderDefaults()` 查表获取。

## 三、Image 图片生成

### 3.1 ImageClient API

构造函数 `new ImageClient()`，从 `settingsStore.imageGen` 读取配置。API Key 缺失时回退到 `llm.apiKey`。

| 方法 | 说明 |
|---|---|
| `generate(prompt, cacheKey)` | 生成图片，返回 data URL。先查 IndexedDB 缓存，命中直接返回；未命中则调 API 并写入缓存 |

### 3.2 Image Provider

实际 `ImageClient.fetchImage()`（`ImageClient.ts:75-118`）只有 `'openai'` 和 `'custom'` 两个独立分支；`'sd'` 走 Custom 通用回退路径。

| Provider | 实现方式 | 备注 |
|---|---|---|
| **OpenAI** | POST DALL-E API，`response_format: b64_json`，从 `data[0].b64_json` 提取 | 独立分支 (`provider === 'openai'`) |
| **Stable Diffusion** | **无独立实现**——走 Custom 通用路径 (POST 端点, `response_format: url`, fetch URL → base64) | ⚠️ SD 端点 (如 AUTOMATIC1111 / SD WebUI) 返回格式**不兼容 OpenAI 兼容模式**时, 会**静默失败**返回 `null`, UI 不报错 |
| **Custom** | OpenAI 兼容路径，优先尝试 `b64_json`，回退到 URL 模式 | 独立分支 (`provider === 'custom'`), 同时作为 SD 兜底 |

所有 Provider 均尝试返回 `data:image/png;base64,...` 格式的 data URL。如果 SD 端点返回格式不符（缺 `data` 字段、缺 `b64_json` / `url`），`fetchImage()` 返回 `null` 而不抛错——这是已知限制，列入后续需要改进项。

### 3.3 IndexedDB 缓存

| 属性 | 值 |
|---|---|
| 数据库名 | `aeslan-images` |
| 版本 | `1` |
| Object Store | `generated` |
| 键类型 | 字符串（cacheKey） |
| 操作 | `getCache(key)` / `setCache(key, base64)` |

先查缓存再请求 API，避免重复生成同一张图。写入失败静默忽略。

### 3.4 配置

`ImageGenConfig { provider, apiKey, endpoint, model, size, quality }`

| 配置项 | 默认值 |
|---|---|
| `provider` | `'openai'` |
| `model` | `'dall-e-3'` |
| `size` | `'1024x1024'` |
| `quality` | `'standard'` |
| `imageGenEnabled` | `false` |

`quality` 仅对 `dall-e-3` 模型生效。

## 四、STT 语音输入

### 4.1 useVoiceInput Hook

`useVoiceInput()` 返回 `{ isListening, transcript, isSupported, start, stop }`。

| 返回值 | 说明 |
|---|---|
| `isListening` | 当前是否正在监听 |
| `transcript` | 识别结果文本（最终结果覆盖） |
| `isSupported` | 浏览器是否支持 SpeechRecognition API |
| `start()` | 开始监听。Browser provider 走 Web Speech API；其他 provider 走 MediaRecorder 录制→发送 STT API |
| `stop()` | 停止监听并清理资源 |

**双路径设计**：
- **Browser 路径**：`SpeechRecognition` API，`lang = stt.language`，`interimResults = true`，`continuous = false`
- **Custom 路径**：`navigator.mediaDevices.getUserMedia({ audio: true })` → `MediaRecorder`（`audio/webm`）→ `stop` 时 `new Blob(chunks)` → `sendToSTTAPI()`

> `sendToSTTAPI` 是 `services/stt/STTClient.ts` 中的**独立导出函数**（不是 `useVoiceInput` 内部方法），允许其他模块（如音频转写工作流、第三方组件）直接调用。签名：`sendToSTTAPI(audio: Blob, config: STTConfig): Promise<string>`，内部根据 `config.provider` 走 Whisper/MiMo/Custom 路径后返回转写文本。

### 4.2 四 Provider

| Provider | 实现方式 |
|---|---|
| **Browser** | Web Speech API (`SpeechRecognition`)，免费，无需 API Key |
| **OpenAI** | Whisper API：`POST /v1/audio/transcriptions`，FormData 上传 `audio.webm` |
| **MiMo** | 统一 chat 端点，`buildMimoTranscriptionRequest` 将音频 base64 编码为消息，`extractChatResponseText` 提取文本 |
| **Custom** | OpenAI 兼容路径（Whisper 格式） |

`normalizeSTTLanguage()` 将 `zh-CN` 类语言码转为 `zh` 供 API 使用。

### 4.3 语言配置

- 默认语言：`zh-CN`
- Browser provider 直接使用 `stt.language` 设置 `rec.lang`
- API provider 通过 `normalizeSTTLanguage()` 处理（`zh-*` → `zh`）

### 4.4 配置

`STTConfig { provider, apiKey, endpoint, model, language }`

| 配置项 | 默认值 |
|---|---|
| `provider` | `'browser'` |
| `model` | `'whisper-1'` |
| `language` | `'zh-CN'` |

## 六、规划

期望进一步优化 TTS 流式播放体验，实现首句生成即开始播放，将感知延迟降至最低，让语音输出如真人对话般自然流畅。

期待图片生成支持批量产出与画廊式浏览，让玩家能够一次性生成多张场景插图，并在一个统一的视觉空间中回顾与管理所有生成的画面。

希望将 TTS 能力扩展至多语言领域，覆盖日语、英语、韩语等主要语言的语音输出，让不同语言背景的玩家都能沉浸在母语的叙事声中。

展望对视频与动画生成技术的探索，为未来可能的过场动画、场景动效等更丰富的媒体表现形态奠定基础。
