# 物品系统

## 一、介绍

物品系统（Item System）是 OpenTaleRunner 的核心数据与玩法支撑模块，负责管理游戏世界中所有物品的定义、生成、存储、装备和流转。系统定义了 **7 大分类**、**6 档品质**和 **11 种效果类型**，覆盖可装备武器/护甲/饰品、一次性消耗品、材料、关键物品和容器等全部物品形态。

**背包与装备槽**：角色物品栏（`Inventory`）由装备槽（`equipped`）和背包（`backpack`）两部分组成。装备槽承载武器、护甲、饰品三类可装备物品，背包则容纳其余物品。货币独立为 `currency: { gold, silver, copper }` 子系统。

**物品历史追踪**：每件物品从获取到升级、转化，均携带完整的时间线记录（`history[]`），支持溯源物品的完整生命周期——何时获得、经历过何种锻造/附魔、被 GM 如何重新定义。

**GM 驱动生成**：物品的创建、获取、修改和丢失均由 GM（LLM）通过叙事引擎驱动——PM 引擎的 `NarrativeResponse.consequences` 返回 `itemsGained`、`itemsLost`、`itemsModified` 数据，客户端 `applyConsequences()` 据此驱动物品系统的所有增删改操作。

## 二、设计

### 2.1 Item 数据模型

Item 接口定义 20+ 字段，所有可选字段有默认值，统一由 `normalizeItem()` 填充。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `itemId` | `string` | 否 | 唯一标识，默认 `item_{timestamp}_{random}` |
| `name` | `string` | 是 | 物品名称 |
| `category` | `ItemCategory` | 否 | 七分类之一，默认 `'consumable'` |
| `subCategory` | `string` | 否 | 子分类（如"长剑"所属的"剑"），默认 `''` |
| `quality` | `ItemQuality` | 否 | 六档品质，默认 `'普通'` |
| `quantity` | `number` | 否 | 堆叠数量，默认 `1` |
| `description` | `string` | 否 | 物品描述文本，默认 `''` |
| `effects` | `ItemEffect[]` | 否 | 效果列表，默认 `[]` |
| `value` | `number` | 否 | 基础价值，默认 `0` |
| `durability` | `number` | 否 | 当前耐久度（可空） |
| `maxDurability` | `number` | 否 | 最大耐久度（可空） |
| `history` | `ItemHistoryEntry[]` | 否 | 历史记录数组，默认 `[]` |
| `createdAt` | `string` | 否 | 创建时间 ISO 字符串，默认当前时间 |
| `source` | `string` | 否 | 来源（NPC 名/地点/事件），默认 `''` |
| `equipped` | `boolean` | 否 | 是否已装备 |
| `equipSlot` | `'weapon' \| 'armor' \| 'accessory'` | 否 | 装备槽位 |
| `canBeEquipped` | `boolean` | 否 | 是否可装备 |
| `canBeUsed` | `boolean` | 否 | 是否可使用 |
| `usePrompt` | `string` | 否 | 使用时的提示文本 |

**normalizeItem()** 位于 `client/src/types/item.ts:68`，接收 `Partial<Item>`，补全所有默认值并返回合法 `Item` 对象。核心逻辑：

```typescript
export function normalizeItem(partial: Partial<Item>): Item {
  return {
    itemId: partial.itemId || `item_${Date.now()}_${Math.random().toString(36).slice(2, 8)}`,
    name: partial.name || '未知物品',
    category: partial.category || 'consumable',
    subCategory: partial.subCategory || '',
    quality: partial.quality || '普通',
    quantity: partial.quantity ?? 1,
    description: partial.description || '',
    effects: partial.effects || [],
    value: partial.value || 0,
    durability: partial.durability,
    maxDurability: partial.maxDurability,
    history: partial.history || [],
    createdAt: partial.createdAt || new Date().toISOString(),
    source: partial.source || '',
    equipped: partial.equipped,
    equipSlot: partial.equipSlot,
    canBeEquipped: partial.canBeEquipped,
    canBeUsed: partial.canBeUsed,
    usePrompt: partial.usePrompt,
  };
}
```

### 2.4 11 种效果类型

每种效果由 `ItemEffect` 接口定义，包含 4 个字段：

```typescript
interface ItemEffect {
  id: string;
  type: EffectType;
  value: number | string | Record<string, unknown>;
  description: string;
}
```

| 效果类型 | 英文标识 | value 类型 | 说明 | 参与判定？ |
|----------|----------|-----------|------|-----------|
| 伤害加成 | `damage_bonus` | `number` | 直接增加伤害值 | 是（计入 equipmentBonus） |
| 防御加成 | `defense_bonus` | `number` | 减少受到的伤害 | 否 |
| 属性修正 | `attribute_mod` | `Record<string, number>` | 如 `{ STR: 2, DEX: 1 }` | 是（仅 STR/DEX） |
| 生命恢复 | `hp_restore` | `number` | 恢复 HP 值 | 否 |
| 生命上限 | `hp_max_bonus` | `number` | 增加最大 HP | 否 |
| 体力恢复 | `vital_restore` | `number` | 恢复体力值 | 否 |
| 元素伤害 | `elemental_damage` | `string \| Record` | 附加元素伤害 | 否（v0.4 规划接入） |
| 元素抗性 | `elemental_resist` | `string \| Record` | 减少元素伤害 | 否（v0.4 规划接入） |
| 技能加成 | `skill_bonus` | `number` | 提升技能等级 | 是（计入 skillBonus） |
| 光源 | `light_source` | `boolean`（标记） | 是否携带光源的开关（`JudgmentSystem.ts:54-55` `result.hasLightSource = true` 与 `:96-104` `checkLightSource()` 判定），v0.1 无亮度数值概念 | 是（影响夜间惩罚） |
| 特殊 | `special` | 任意 | 自定义效果 | 否 |

**判定系统交互**：效果参与 2d6 判定公式时分为三类处理（参见 `判定系统.md` 2.6 节）：
- **直接计入 equipmentBonus**：`damage_bonus`、`attribute_mod`（STR/DEX）
- **计入 skillBonus**：`skill_bonus`
- **影响夜间惩罚**：`light_source`
- **忽略**：`hp_restore`、`hp_max_bonus`、`vital_restore`、`special`

### 2.5 背包与装备系统

`Inventory` 结构（`client/src/types/character.ts:28`）：

```typescript
interface Inventory {
  equipped: {
    weapon: Item | null;
    armor: Item | null;
    accessory: Item | null;
  };
  backpack: Item[];
  currency: {
    gold: number;
    silver: number;
    copper: number;
  };
}
```

**装备槽**：每个槽位只能装备一件物品。穿戴时将物品从 `backpack` 移入对应 `equipped` 槽位，卸下时反向操作。装备操作触发钩子 `item.onEquip`（参见 `GameRuleEngine中间件设计文档.md` 3.2 节）。

**背包**：`backpack` 为数组，允许同名消耗品和材料的 `quantity` 字段堆叠。GM 返回 `itemsGained` 时，`applyConsequences()` 自动检测同名同分类物品并叠加数量（见 2.7 节）。

**货币**：三币制——金币（gold）、银币（silver）、铜币（copper）。GM 可通过 `ConsequenceData.currencyChange` 增减货币。

**updateInventory()**：替换整个 `inventory` 对象（非补丁式更新），调用者需先展开旧状态再合并变更。定义于 `characterStore`，由 `applyConsequences()` 统一调用。

### 2.6 物品历史追踪

每件物品携带 `history: ItemHistoryEntry[]` 数组，记录完整生命周期：

```typescript
interface ItemHistoryEntry {
  timestamp: string;         // ISO 时间戳
  event: string;             // 事件类型：acquired / upgraded / transformed
  description: string;       // 事件描述
  oldName?: string;          // 旧名称（升级时）
  oldDescription?: string;   // 旧描述（升级时）
  addedEffects?: ItemEffect[];  // 新增效果（转化时）
  removedEffects?: string[];    // 移除效果 ID（转化时）
  location?: string;         // 获取地点
  relatedNPC?: string;       // 相关 NPC
}
```

**三种事件类型**：

- **`acquired`** — 物品首次获得。记录获取时间、来源描述、地点和 NPC。
- **`upgraded`** — 物品升级（通过 `replacesItemId`）。保留旧物品的全部历史，追加新条目，记录 `oldName`、`oldDescription`。
- **`transformed`** — 物品转化（通过 `itemsModified`）。记录 GM 对物品重命名、品质变更、效果增减等操作，追加转化事件到历史。

**升级链示例**：

```
"铁剑" (Day 5 acquired)
  → "精钢长剑" (Day 12 upgraded, replacesItemId)
    → "烈焰之刃" (Day 20 transformed, 新增火焰伤害效果)
```

历史数组保留完整链条：
```json
[
  { "event": "acquired", "description": "在铁匠铺购买", "timestamp": "..." },
  { "event": "upgraded", "oldName": "铁剑", "description": "升级为精钢长剑", "timestamp": "..." },
  { "event": "transformed", "addedEffects": [{...}], "description": "附魔火焰伤害", "timestamp": "..." }
]
```

### 2.7 物品增删改（后果系统）

全部物品操作经由 `applyConsequences()`（`client/src/services/consequence/applyConsequences.ts:77`）处理，接收 GM 返回的 `ConsequenceData`，分为三种操作：

#### 获得物品（itemsGained）

```typescript
interface ItemGainedData {
  name: string;
  category?: string;
  subCategory?: string;
  quality?: string;
  quantity?: number;
  description?: string;
  effects?: Array<{ type?: string; value?: number | string | Record<string, unknown>; description?: string }>;
  replacesItemId?: string;  // 非空 = 升级旧物品
}
```

处理逻辑：

1. **升级模式**（`replacesItemId` 非空）：在背包中查找匹配 `itemId` 的物品作为 `oldItem`，调用 `buildItemFromGained(gained, oldItem, now)` 生成新物品，保留旧物品的 `createdAt`、`history`、`durability` 等字段，在历史中追加 `upgraded` 事件。
2. **新增模式**（`replacesItemId` 为空）：在背包中查找同名同分类物品。若找到且 `quantity > 0`，则叠加数量；否则调用 `buildItemFromGained(gained, null, now)` 创建新物品并 `push` 入背包。

#### 失去物品（itemsLost）

```typescript
interface ItemLostData {
  itemId?: string;
  name?: string;
  quantity?: number;
}
```

处理逻辑：

- 优先按 `itemId` 精确匹配，其次按 `name` 匹配
- 若指定 `quantity` 且当前数量 > 失去数量 → 扣减数量
- 否则从背包中 `splice` 删除整件物品

#### 修改物品（itemsModified）

```typescript
interface ItemModifiedData {
  itemId: string;
  newName?: string;
  newQuality?: string;
  description?: string;
  addedEffects?: Array<{ type?: string; value?: number | string | Record<string, unknown>; description?: string }>;
  durabilityChange?: number;
}
```

处理逻辑（`applyItemModification()`）：

1. 按 `itemId` 在背包中查找目标物品
2. 原地修改（mutation）：更新 `name`、`quality`、`description`、`durability`
3. 追加 `addedEffects` 到效果列表
4. 在 `history` 中追加 `transformed` 事件

所有三种操作最终通过 `characterStore.updateInventory()` 写入 store，触发 UI 更新。

## 三、规划

期望打造直观的装备对比界面，让玩家在 hover 装备时即刻感知属性差异、品质差距和耐久对比，告别盲目的装备选择。同步推进物品合成与锻造系统，消耗材料类物品生成新造物，让采集与创造形成完整的工匠循环——合成产物继承原料的历史记忆，每一件作品都承载着旅途的痕迹。

在此基础上，构建物品交易体系——无论是玩家间的互惠交换，还是与 NPC 商店的声望折扣交易，都需要双方确认、货币与物品原子化转移的可靠流程。配合装备耐久消耗与修理机制，让武器和护甲在战斗中真实磨损，耐久归零后效果失效但不可毁坏，修理则需匹配消耗品或求助 NPC 铁匠。

远期期望引入程序化物品生成，以前缀/后缀词缀系统赋予每一件物品独一无二的个性——"锋利的"、"烈焰的"等前缀附加伤害或元素效果，"··· of the Bear"等后缀改写属性修正，品质决定词缀数量与稀有池，让艾瑟兰大陆上不存在两件完全相同的装备。

## 四、v0.4 增量

### 4.3 共享 UI 组件 (与 UI 通用化联动)

- **`ItemChip`** — 装备槽 / 背包 / 对比 tooltip 共用的紧凑展示 (`4139362`)
- **`ItemCardRow`** — BackpackModal 物品行 (含 quality 颜色 + 数量 + hover) (`4139362`)
- **`ItemDetailPanel`** — 详情面板，供 BackpackModal / 锻造台 (v0.6) 复用 (`2024aa0`)
- **`ItemEffectList`** — 效果列表，含 affix 词条渲染 (`c311644`)

### 4.4 已知约束 (v0.4 后将解决)

- Affix 抽取目前走确定性 RNG, 不支持 LLM 动态调整词条稀有度 — v0.6
- 13 种 `effectType` 仅在物品属性里生效, 战斗判定中尚未参与减伤 — v0.6
- 物品对比仅支持"装备 vs 背包", 不支持"装备 vs 装备"对比 — 后续
- 物品耐久尚未在战斗/探索中消耗 — v0.8
