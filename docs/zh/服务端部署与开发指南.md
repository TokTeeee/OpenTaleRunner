# 服务端部署与开发指南

## 环境要求

> 本指南需 `Python 3.10+`（`server/config.py` 等模块使用 `int | None` PEP 604 语法，3.10+ 原生支持）。3.11+ 同样兼容。

- Python 3.10+
- pip

## 快速启动

```bash
cd G:\OpenTaleRunner\server

# 1. 安装依赖
pip install -r requirements.txt

# 2. (可选) 配置LLM Key用于编年史聚合
set SERVICE_LLM_KEY=sk-xxx

# 3. 启动主API (端口8000)
python run.py

# 4. 另开终端启动看板 (端口8081)
python run_dashboard.py
```

> 仓库目前不提供一键启动脚本，需手动启动两个服务（主 API `python run.py`、Dashboard `python run_dashboard.py`）。如需简化启动可自行编写 `start-server.ps1`。

## 配置

所有配置通过环境变量：

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SERVICE_PORT` | 8000 | 主API监听端口 |
| `SERVICE_LLM_KEY` | (空) | 大PM编年史聚合用LLM API Key |
| `SERVICE_LLM_ENDPOINT` | `https://api.deepseek.com/chat/completions` | LLM端点 |
| `SERVICE_LLM_MODEL` | `deepseek-chat` | 模型名 |
| `SERVICE_LLM_TEMPERATURE` | `0.7` | LLM 温度参数 |
| `SERVICE_LLM_MAX_TOKENS` | `2048` | LLM 最大输出 token |
| `SERVICE_JWT_SECRET` | **(必填，无默认值)** | 未设置时 `config.Settings.__post_init__` 直接 `sys.exit(1)` 退出；请使用强随机字符串作为签名密钥 |
| `SERVICE_JWT_EXPIRE_HOURS` | `72` | JWT Token 有效期（小时） |
| `SERVICE_DB_PATH` | `./data/aeslan.db` | SQLite数据库路径 |
| `SERVICE_DATA_DIR` | `./data` | 种子数据目录 |
| `SERVICE_CORS_ORIGINS` | `http://localhost:5173,http://localhost:3000` | CORS 允许源（已带 `http://` 前缀） |
| `SERVICE_RATE_LIMIT` | 60 | 速率限制请求数 |
| `SERVICE_RATE_WINDOW` | 60 | 速率限制窗口（秒） |

**SERVICE_LOG_* 系列：**

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `SERVICE_LOG_ENABLED` | `true` | 是否启用文件日志 |
| `SERVICE_LOG_LEVEL` | `INFO` | 日志级别 |
| `SERVICE_LOG_DIR` | `<server_dir>/logs` | 日志目录 |
| `SERVICE_LOG_FORMAT` | `text` | `text` 或 `json` |
| `SERVICE_LOG_MAX_BYTES` | `10485760` (10MB) | 单文件最大字节数 |
| `SERVICE_LOG_BACKUP_COUNT` | `7` | 备份保留数 |
| `CHRONICLE_AGGREGATE_MIN_LOGS` | `1` | 触发编年史聚合的最小日志数 |
| `STORYBOOK_PATH` | `./data/storybook.json` | 故事书 JSON 路径 |
| `CLIENT_PORT` | `3000` | 客户端 dev server 端口 |

## 日志

> `server/logging_config.py` 使用 `RotatingFileHandler`，**按大小滚动**（默认 10MB/文件，保留 7 个备份）。`LOG_DIR` 下日志文件名是 `service.log`（不是 `YYYY-MM-DD.log`）。

日志写入 `server/logs/service.log`（按 10MB 大小滚动，保留 7 份）。模块级日志标签：
- `api` — 服务启动/停止
- `db` — 数据库操作
- `chronicle` — 编年史聚合
- `npc` — NPC操作
- `ghost` — 幽灵NPC
- `dashboard` — 看板
- `request` — 请求日志
- `llm` — LLM 调用日志

## 端口占用处理

> `run.py` / `run_dashboard.py` 不做端口检测——若端口被占用需手动处理（Windows: `netstat -ano | findstr :8000` + `taskkill /PID <pid> /F`）。

## 数据库重置

```bash
del server\data\aeslan.db
# 重启服务端即可自动建表+种子数据
```

## 扩展指南

### 替换数据库为PostgreSQL

1. 新建 `db/postgres_database.py` 实现 `Database` 接口
2. 新建 `repositories/postgres_xxx_repo.py` 实现各Repository接口
3. 修改 `routers/deps.py` 中的工厂函数指向新实现

**Router和Service层零改动。**

### 添加新API端点

1. `models/` 中新增Pydantic模型
2. `repositories/` 中新增数据访问方法
3. `services/` 中新增业务逻辑
4. `routers/` 中新增路由文件
5. `main.py` 中注册路由

### 添加新的种子数据

修改 `services/terrain_service.py` 或 `services/event_generator.py` 中的种子数据定义，重启服务即可自动加载。

## 三、规划

期望在容器编排层面迈向生产级部署，提供 Kubernetes Helm Chart 模板，配合 Nginx 反向代理与 Let's Encrypt 自动化 SSL/TLS 证书管理，同时内置健康检查端点，确保服务高可用与可观测。

进一步规划数据库与缓存的升级路径——提供从 SQLite 到 PostgreSQL 的迁移指南与自动化脚本，引入 Redis 缓存层以加速热点数据访问，并支持多 worker 负载均衡配置，使服务端具备横向扩展能力。

长期愿景是覆盖主流云平台的一键部署模板（AWS、GCP、Azure），配套 CI/CD 自动发布流水线与蓝绿部署策略，让团队能够以零运维心智负担完成从开发到生产的全流程交付。
