# 战斗系统

## 一、介绍

战斗系统（Combat System）是 v0.4 引入的回合制战斗模块，负责管理玩家与敌对生物的对抗流程。系统采用 **ACT 队列**（按先攻排序）+ **6 维属性公式** 的混合机制，将每次行动映射为明确的命中/伤害/状态变化。

**核心概念：**

- **ACT 队列（initiative queue）**：每个战斗开始时按 `d20 + effectiveDEX` 计算先攻，按降序排列，所有战斗者轮流行动。
- **6 维属性（six attributes）**：力量（STR）/敏捷（DEX）/体质（CON）/智力（INT）/感知（WIS）/魅力（CHA）。其中 **STR 影响近战伤害**，**DEX 影响命中与先攻**，**CON 影响 HP 上限**。
- **AP（Action Points）行动点**：每回合开始时重置为 `maxAp=6`，每个动作消耗 1~4 AP。详见第三节。
- **5 阶段 FSM**：战斗的有限状态机分为 `idle → initializing → active → resolving → settled` 五阶段。
- **4 档难度（balance rating）**：`trivial / normal / hard / deadly`，决定先攻评估与失败惩罚。

> v0.4 战斗系统由 4 个核心模块构成：**CombatEngine**（流程编排）、**ActionResolver**（行动解析）、**combatTools**（GM toolcall 协议）、**CombatView**（UI 呈现）。详情见[客户端架构](Client-Architecture.md)。

## 二、设计

### 2.1 战斗流程概览

```
  触发 startCombat (GM toolcall)
          │
          ▼
  ┌──────────────────┐
  │  initializing    │ ── 校验 payload + 算 BalanceReport
  └──────────────────┘
          │
          ▼
  ┌──────────────────┐
  │     active       │ ── ACT 队列循环 (turn 推进)
  │  (回合制)        │    每回合: 玩家 + 敌人轮流行动
  └──────────────────┘
          │
          │ 战斗结束 (任意一方 HP=0 或 全员逃跑/打断)
          ▼
  ┌──────────────────┐
  │   resolving      │ ── 计算 outcome (victory/defeat/fled/...)
  └──────────────────┘
          │
          ▼
  ┌──────────────────┐
  │    settled       │ ── 写 narrativeClosing + 应用失败惩罚
  └──────────────────┘
          │
          ▼
       idle (回到探索)
```

**关键点：**
- `idle → initializing` 守卫：避免重复启动战斗
- `active → resolving` 守卫：玩家或敌人 HP=0 触发；不允许 `active → idle` 直跳
- `settled → idle`：endCombat handler 内部 reset，写入玩家 finalState

### 2.2 6 维公式

战斗的伤害与命中计算基于 6 维属性。每个 combatant 的**有效属性**等于基础属性 + 所有 buff 的 `modifiers` 累加：

```
effectiveSTR = baseSTR + Σ buff.modifiers.STR
effectiveDEX = baseDEX + Σ buff.modifiers.DEX
```

**近战伤害公式：**

```
damage = max(1, d6 + effectiveSTR // 2 + weapon.damage_bonus - target.defense)
```

其中：
- `d6`：1d6 骰子（基础随机性）
- `effectiveSTR // 2`：力量修正，`floor(STR/2) - 5`
- `weapon.damage_bonus`：装备武器的伤害加成
- `target.defense`：目标装备的防御值（皮甲 +1、板甲 +3 等）

**命中判定（d20 规则）：**

```
attackRoll = d20 + effectiveDEX // 2
hit = attackRoll >= target.evasion (默认 10 + DEX // 2)
```

> 命中与伤害是分开两步：先投 d20 判定命中，再投 d6 计算伤害。装备 `accuracy` 效果影响攻击加值，`defense` 影响敌方命中。

### 2.3 AP=6 行动点

每回合开始时，所有 combatant 的 `ap` 复位为 `maxAp=6`（战旗风格）。每个动作消耗不同 AP：

| 动作 | AP 消耗 | 效果 |
|------|---------|------|
| `attack` 攻击 | 1 | 投 d20 命中 + 投 d6 伤害 |
| `defend` 防御 | 2 | +2 AC，下回合受击 -50% 伤害 |
| `skill` 技能 | 1~4 | 视技能等级（1~4 AP） |
| `item` 物品 | 1 | 消耗背包里物品的 use 效果 |
| `wait` 等待 | 0 | 跳过本回合，AP 留给下回合 |
| `flee` 逃跑 | 2 | 投 d20 + DEX；失败则本回合无行动 |

> 怪物默认 `maxAp=4`（4 mob 行为节奏），玩家与 NPC 默认 `maxAp=6`。这是 v0.4 的非对称设计：玩家有更多动作空间，怪物以少换精。

### 2.4 QTE 简述

**QTE（Quick Time Event）**是 v0.4 引入的时机操作层，在玩家执行某些动作时弹出限时输入：

| QTE 类型 | 触发时机 | 操作 |
|---------|---------|------|
| 攻击 QTE | 玩家 `attack` 时 | 点击 0.5s 窗口期，按住时长影响伤害（±20%） |
| 防御 QTE | 玩家 `defend` 时 | 0.3s 闪避窗口，准确点击 +30% 闪避率 |
| 技能 QTE | 玩家 `skill` 时 | 特定技能要求精准输入（e.g. 法师吟唱 QTE 链） |

QTE **不强制**：失败仅失去 QTE 增益（伤害/闪避率下调），不会反噬。QTE 适合节奏战斗调试，让玩家在慢思考与快操作间切换。

### 2.5 4 档失败惩罚

战斗失败（`outcome=defeat`）时，endCombat handler 按 `appliedBalanceRating` 应用失败惩罚：

| 难度 | 伤害 | 扣金比例 | 附加 condition | 必活 (survives) |
|------|------|---------|---------------|-----------------|
| `trivial` | `none` | 0% | 无 | true |
| `normal` | `minor`（-10% HP） | 10% | `wounded_1` | true |
| `hard` | `major`（-30% HP） | 30% | `wounded_2`, `exhausted` | true |
| `deadly` | `death-narrative`（HP→0） | 50% | `perma-wound`（永久） | **true**（剧情濒死替代真死） |

**`survives=true` 的意义**：即便 HP=0，玩家不会真死；会进入"濒死剧情"分支，注入 `perma-wound` 作为代价。这是 v0.4 的"玩家永远能继续玩"设计哲学，详见 combatTools.ts `endCombatHandler`。

> 失败惩罚只对真实 `defeat` / `disrupted` 结局生效。`victory` / `fled` 走 loot 路径，**不**应用失败惩罚。

## 三、调试模式

### 3.1 入口

在标题页底部有一个低调的 **🐞 调试模式** 按钮（minimal 样式，不抢主按钮视线）。点击后弹出 4 张预设战斗卡。

调试模式用于开发与测试 v0.4 战斗系统各功能，**完全跳过 LLM**：点击战斗卡后，client 直接 dispatch `startCombat` toolcall，进入战斗 UI 立即可用，不需要 PM 引擎介入。

### 3.2 4 档预设

| 卡 | 难度 | 怪物 | 测试目标 |
|----|------|------|---------|
| **路边小怪** | `trivial` | 1× 哥布林斥候 (HP 8) | 6 维公式与攻击基础流程 |
| **哥布林伏击** | `normal` | 3× 哥布林斥候 | 多敌 ACT 队列与群战逻辑 |
| **哥布林精英队** | `hard` | 1× 哥布林战士 (HP 25) + 1× 斥候 | 防御动作与物品使用 |
| **巨魔首领** | `deadly` | 1× 巨魔首领 (HP 60) | deadly 档失败惩罚 (perma-wound) |

每张卡描述了**预期结果**（回合数、是否触发 QTE、是否触发惩罚），方便回归测试。

### 3.3 合成玩家

调试模式的玩家是**预设合成角色**"测试勇者"：

- **属性**：STR 14 / DEX 16 / CON 12 / INT 10 / WIS 15 / CHA 13
- **资源**：HP 30 / AP 6
- **装备**：铁剑（+4 攻击）、皮甲（+1 防御）、无饰品

合成玩家**完全独立**于你的真实角色存档：
- 不读取 `characterStore.character`
- 不写入 `characterStore`（即便战斗失败，金币 / 条件 / HP 都不会被改）
- 调试战斗**不污染**你的游戏进度

### 3.4 自动重开

战斗结束后（无论胜负），modal 会自动重开，让你可以立即再选一档。这是个开发效率设计——不需要每场战斗都点回标题页。

如需在战斗中退出，直接点 [X] 关闭 modal 即可。战斗会按 endCombat handler 的清理流程回归 `idle` 状态。

### 3.5 注意事项

- 调试模式只在标题页可用，战斗中无法打开新调试战斗
- 怪物工厂（`goblinScout` / `goblinWarrior` / `trollChief`）是测试用**固定数值**，不随 LLM 调参变化
- 调试战斗走完整的 5 阶段 FSM + 失败惩罚流程，**所有回归测试**都应能在此处复现

## 五、v0.4 增量

战斗系统是 v0.4 一次性交付的完整子系统，已记录在本文「二、设计」「三、调试模式」两章。本节汇总 v0.4 关键交付物与版本对齐信息。

### 5.1 组件清单 (7 个 UI + 4 个 service)

- **UI** — `CombatView` (主面板) / `CombatField` (战场) / `CombatantCard` (参战者卡) / `ActionMenu` (玩家行动菜单) / `ACTQueueBar` (先攻队列) / `QTETimingBar` / `QTETypingBox` (QTE 节奏 + 打字) / `FloatingDamage` / `CombatLog` (滚动日志)
- **Service** — `CombatEngine` (主引擎) / `ActionResolver` (命中 + 伤害) / `BalanceEvaluator` (平衡评估) / `BuffManager` (Buff/Debuff) / `QTELayer` (QTE 调度) / `ItemCallbackRouter` (物品钩子) / `combatTools` (toolcall 定义) / `debugCombatStarter` (Debug 入口) / `dice` (2d6 投骰) / `effectTypeCompat` (13 种 effectType 战斗兼容映射)
- **Store** — `combatStore` (战斗状态机: idle / setup / rolling / acting / resolution / ended)

### 5.2 状态机 (5 阶段)

```
idle → setup → rolling → acting → resolution → ended → idle
```

每阶段由 `CombatEngine` 推进, 玩家行动 (action menu 选 attack / skill / item / defend / flee) 触发 `ActionResolver` 计算命中与伤害, 命中后 `BalanceEvaluator` 评估双方均势, `BuffManager` 维护 buff/debuff 时序, `QTELayer` 在合适时机插入 QTE 节奏校验。

### 5.3 Debug Mode (与正式战斗隔离)

仅在标题页可用, 怪物工厂 `goblinScout` / `goblinWarrior` / `trollChief` 是固定数值, 调试战斗**不读不写** `characterStore`, 战斗结束 modal 自动重开便于反复回归。

### 5.4 GM 触发入口 (toolcall)

`PMEngine` 通过 toolcall `startCombat` / `endCombat` 把战斗与叙事融合:

- `startCombat({ enemies, party, terrain })` — 创建 combat session, 写入 `combatStore.session`
- `endCombat({ outcome, loot })` — 关闭 session, 物品按 v0.4 affix 池走 `applyConsequences.itemsGained`
