# 战斗系统

## 一、介绍

战斗系统（Combat System）是 v0.4 引入的回合制战斗模块，负责管理玩家与敌对生物的对抗流程。系统采用 **ACT 队列**（按先攻排序）+ **6 维属性公式** 的混合机制，将每次行动映射为明确的命中/伤害/状态变化。

**核心概念：**

- **ACT 队列（initiative queue）**：每个战斗开始时按 `d20 + effectiveDEX` 计算先攻，按降序排列，所有战斗者轮流行动。
- **6 维属性（six attributes）**：力量（STR）/敏捷（DEX）/体质（CON）/智力（INT）/感知（WIS）/魅力（CHA）。其中 **STR 影响近战伤害**，**DEX 影响命中与先攻**，**CON 影响 HP 上限**。
- **AP（Action Points）行动点**：每回合开始时重置为 `maxAp=6`，每个动作消耗 1~4 AP。详见第三节。
- **5 阶段 FSM**：战斗的有限状态机分为 `idle → initializing → active → resolving → settled` 五阶段。
- **4 档难度（balance rating）**：`trivial / normal / hard / deadly`，决定先攻评估与失败惩罚。

> v0.4 战斗系统由 4 个核心模块构成：**CombatEngine**（流程编排）、**ActionResolver**（行动解析）、**combatTools**（GM toolcall 协议）、**CombatView**（UI 呈现）。详情见[客户端架构](Client-Architecture.md)。

## 二、设计

### 2.1 战斗流程概览

```
  触发 startCombat (GM toolcall)
          │
          ▼
  ┌──────────────────┐
  │  initializing    │ ── 校验 payload + 算 BalanceReport
  └──────────────────┘
          │
          ▼
  ┌──────────────────┐
  │     active       │ ── ACT 队列循环 (turn 推进)
  │  (回合制)        │    每回合: 玩家 + 敌人轮流行动
  └──────────────────┘
          │
          │ 战斗结束 (任意一方 HP=0 或 全员逃跑/打断)
          ▼
  ┌──────────────────┐
  │   resolving      │ ── 计算 outcome (victory/defeat/fled/...)
  └──────────────────┘
          │
          ▼
  ┌──────────────────┐
  │    settled       │ ── 写 narrativeClosing + 应用失败惩罚
  └──────────────────┘
          │
          ▼
       idle (回到探索)
```

**关键点：**
- `idle → initializing` 守卫：避免重复启动战斗
- `active → resolving` 守卫：玩家或敌人 HP=0 触发；不允许 `active → idle` 直跳
- `settled → idle`：endCombat handler 内部 reset，写入玩家 finalState

### 2.2 6 维公式

战斗的伤害与命中计算基于 6 维属性。每个 combatant 的**有效属性**等于基础属性 + buff 的 `modifiers` 累加 + 装备 `attribute_mod` 加成：

```
effectiveSTR(c) = c.attributes.STR + Σ buff.modifiers.STR + Σ equipment.attribute_mod.STR
effectiveDEX(c) = c.attributes.DEX + Σ buff.modifiers.DEX + Σ equipment.attribute_mod.DEX
```

> **D&D 风格修正值**（v0.5-dev 采用）：`STR_mod = floor((effectiveSTR - 10) / 2)`，DEX 修正同理。
> 例：STR 14 → +2 修正；STR 6 → -2 修正。完整表见 2.2.4。

#### 2.2.1 命中投 (toHit)

```
toHit = d20 + STR_mod
```

- `d20`：1d20（20 面骰，范围 1-20）
- `STR_mod`：`floor((effectiveSTR - 10) / 2)`

> 说明：v0.5-dev 把命中加值从 DEX 改为 STR（更符合"近战靠力量、定身靠敏捷"的直觉）。
> 远程武器后续可改用 DEX_mod（Phase 7 接入）。

#### 2.2.2 命中门槛 (hit threshold)

```
threshold = 10 + DEX_mod + defense + dodgePenalty + (defending ? 2 : 0)
```

- `10`：基础闪避值（未穿甲的角色）
- `DEX_mod`：`floor((effectiveDEX - 10) / 2)` —— 越敏捷越难命中
- `defense`：目标装备护甲的 `defense_bonus` 值
- `dodgePenalty`：连续闪避累积的惩罚（见 2.2.5）
- `defending`：本回合 `defend` 动作的临时标志，命中门槛 +2

#### 2.2.3 命中判定 + 伤害公式

```
hit    = (toHit >= threshold)            // 平局算命中
base   = max(1, d6 + STR_mod + weapon - target.defense)
damage = round(base * (1 + qte * 0.3))   // QTE 缩放
```

- `d6`：1d6（基础伤害随机性）
- `weapon`：`weapon.damage_bonus` 值（无武器时为 0）
- `target.defense`：**伤害公式**里也减成，与命中门槛的 defense 是同一字段（命中用门槛，伤害再减一次）

#### 2.2.4 D&D 风格修正值表

| 有效属性 | 修正值 | 有效属性 | 修正值 |
|---------|--------|---------|--------|
| 1 | -5 | 12-13 | +1 |
| 2-3 | -4 | 14-15 | +2 |
| 4-5 | -3 | 16-17 | +3 |
| 6-7 | -2 | 18-19 | +4 |
| 8-9 | -1 | 20 | +5 |
| 10-11 | 0 | | |

#### 2.2.5 闪避衰减 (dodge decay)

> 机制核心：**连续闪避命中门槛越涨越高，被命中则归零**。

- 每次成功闪避（`toHit < threshold`）→ defender 的 `dodgePenalty += 5`（DODGE_PENALTY_STEP）
- 一旦被命中 → defender 的 `dodgePenalty = 0`（重置）
- 效果：久守必失，鼓励"用防御过渡到反击"，避免无限闪避

**示例：** 敌人 DEX 10（DEX_mod=0），无护甲：
- 回合 1：toHit=12, threshold=10 → 闪避成功, dodgePenalty=5
- 回合 2：toHit=15, threshold=15 → 闪避成功, dodgePenalty=10
- 回合 3：toHit=20, threshold=20 → 闪避成功, dodgePenalty=15
- 回合 4：toHit=10, threshold=25 → 被命中, dodgePenalty=0

### 2.3 AP=6 行动点

每回合开始时，所有 combatant 的 `ap` 复位为 `maxAp=6`（战旗风格）。每个动作消耗不同 AP：

| 动作 | AP 消耗 | 效果 |
|------|---------|------|
| `attack` 攻击 | **2** | 投 d20 命中 → 投 d6 伤害（2.2.3 公式） |
| `defend` 防御 | **1** | 命中门槛 +2（持续到本回合被命中或下一回合） |
| `item` 物品 | **0** | 消耗背包里物品的 use 效果（走 `ItemCallbackRouter`） |
| `wait` 等待 | **0** | 跳过本回合，**恢复 1 点 AP**（受 maxAp clamp） |
| `flee` 逃跑 | **0** | 投 d100；失败则本回合无行动（不扣 AP） |

> **v0.5-dev 变更**：
> - `attack` AP 从 1 调到 **2**（与 `ActionResolver.ACTION_COSTS` 同步，权重近战核心动作）
> - `defend` AP 从 2 调到 **1**（轻防御，频繁可用）
> - `item / wait / flee` AP 统一为 **0**（"被动动作"语义）
> - `wait` 改为"恢复 1 AP 而非留 AP"，配合 `attack=2` 形成"打-打-等"的节奏
>
> **隐藏 `skill` 动作**：v0.5-dev 暂未配套 SkillRegistry，技能系统与魔法系统尚未落地，从 5 类动作中**临时隐藏**。`CombatAction` 联合类型只剩 5 种（attack / item / defend / wait / flee）。SkillRegistry 后续接回。

> 怪物默认 `maxAp=4`（4 mob 行为节奏），玩家与 NPC 默认 `maxAp=6`。这是 v0.4 的非对称设计：玩家有更多动作空间，怪物以少换精。

### 2.4 QTE 简述

**QTE（Quick Time Event）**是 v0.4 引入的时机操作层，在玩家执行某些动作时弹出限时输入：

| QTE 类型 | 触发时机 | 操作 | v0.5-dev 状态 |
|---------|---------|------|---------------|
| 攻击 QTE | 玩家 `attack` 时 | 点击 0.5s 窗口期，按住时长影响伤害 modifier | ✅ UI 已就绪 (`QTEStore` / `QTETimingBar`)，v0.5 接入 |
| 防御 QTE | 玩家 `defend` 时 | 0.3s 闪避窗口，准确点击 +30% 闪避率 | 🟡 UI 占位（v0.5 接入） |
| 技能 QTE | 玩家 `skill` 时 | 特定技能要求精准输入（e.g. 法师吟唱 QTE 链） | ❌ **已隐藏**（skill 动作隐藏，QTE 链同步暂停） |

QTE **不强制**：失败仅失去 QTE 增益（伤害/闪避率下调），不会反噬。QTE 适合节奏战斗调试，让玩家在慢思考与快操作间切换。

**QTE 伤害缩放**：无论 QTE 关闭还是 modifier=0，都不影响命中判定（`checkHit` 跑在 QTE 之前），只缩放伤害：

```
damage = round( max(1, d6 + STR_mod + weapon - defense) × (1 + qte.modifier × 0.3) )
```

- `modifier=0` → 伤害 = base
- `modifier=+1` → 伤害 × 1.3（最大 +30%）
- `modifier=-1` → 伤害 × 0.7（最大 -30%）

### 2.5 4 档失败惩罚

战斗失败（`outcome=defeat`）时，endCombat handler 按 `appliedBalanceRating` 应用失败惩罚：

| 难度 | 伤害 | 扣金比例 | 附加 condition | 必活 (survives) |
|------|------|---------|---------------|-----------------|
| `trivial` | `none` | 0% | 无 | true |
| `normal` | `minor`（-10% HP） | 10% | `wounded_1` | true |
| `hard` | `major`（-30% HP） | 30% | `wounded_2`, `exhausted` | true |
| `deadly` | `death-narrative`（HP→0） | 50% | `perma-wound`（永久） | **true**（剧情濒死替代真死） |

**`survives=true` 的意义**：即便 HP=0，玩家不会真死；会进入"濒死剧情"分支，注入 `perma-wound` 作为代价。这是 v0.4 的"玩家永远能继续玩"设计哲学，详见 combatTools.ts `endCombatHandler`。

> 失败惩罚只对真实 `defeat` / `disrupted` 结局生效。`victory` / `fled` 走 loot 路径，**不**应用失败惩罚。

### 2.6 当前战斗规则（v0.5-dev 实际实现）

> 本章基于 v0.5-dev 实际代码（`ActionResolver` / `CombatEngine` / `BalanceEvaluator` / `BuffManager` / `effectTypeCompat`）与对应测试用例总结，描述**当前真正生效**的战斗规则。本节与 §2.2 / §2.3 / §2.4 是「设计 vs 实现」关系——以 §2.6 为准。

#### 2.6.1 战斗资源

| 资源 | 默认值 | 说明 |
|------|--------|------|
| `hp / maxHp` | 玩家 30 / 怪物 12 | 归零触发 `defeat` |
| `mp / maxMp` | 玩家 30 / 怪物 0 | **v0.5-dev 暂未使用**（skill 隐藏） |
| `ap / maxAp` | 玩家 6 / 怪物 4 | 战旗风格；每回合开始**不重置**，但 ACT 第一个行动者 +1 AP（`advanceRound`） |

> **AP 行为细节（与代码同步）**：每回合开始时 `ap` **不**重置为 `maxAp`，而是**当前行动者（queue[0]）** +1 AP。玩家 AP 可在 `attack=2` + `wait=0 + 1` 之间循环。

#### 2.6.2 5 阶段 FSM

```
idle → initializing → active → resolving → settled → idle
```

`combatStore.CombatPhase` 字段为上述 5 个值。

#### 2.6.3 4 档难度

| ratio 区间 | 难度 | rank |
|-----------|------|------|
| `< 0.6` | `trivial` | 0 |
| `[0.6, 1.2)` | `normal` | 1 |
| `[1.2, 2.0)` | `hard` | 2 |
| `≥ 2.0` | `deadly` | 3 |

#### 2.6.4 公式快速查阅

| 项 | 公式 | 源 |
|----|------|------|
| 有效属性 | `effectiveATTR = base + Σ buff.modifiers[attr] + Σ equipment.attribute_mod[attr]` | `effectiveAttribute()` |
| 命中投 | `toHit = d20 + STR_mod` | `rollToHit()` |
| 命中门槛 | `threshold = 10 + DEX_mod + defense + dodgePenalty + (defending ? 2 : 0)` | `hitThreshold()` |
| 命中判定 | `hit = (toHit >= threshold)`（平局算命中）| `checkHit()` |
| 伤害 | `base = max(1, d6 + STR_mod + weapon - target.defense)` | `rollDamage()` |
| QTE 缩放 | `damage = round(base × (1 + qte.modifier × 0.3))` | `rollDamage()` |
| 闪避衰减 | `dodgePenalty += 5 / 命中则归零`（DODGE_PENALTY_STEP=5）| `resolveAttack()` |
| 逃跑概率 | `chance = clamp(0.3 + (DEX_self − avgDEX_others) / 20, 0.1, 0.9)` | `fleeChance()` |
| 逃跑投 | `d100 ≤ chance × 100 → success` | `rollFlee()` |
| 先攻 | `initiative = d20 + DEX_mod` | `CombatEngine.start()` |
| 战斗力 | `power = hp + 2 × Σ attr + weapon + armor + Σ equipment.attribute_mod` | `BalanceEvaluator` |

#### 2.6.5 5 种 CombatAction 行为细节

| 动作 | AP | 公式 / 行为 | 失败处理 |
|------|----|----|---------|
| `attack` | 2 | `toHit >= threshold` → `rollDamage` | 闪避：dodgePenalty += 5 |
| `defend` | 1 | 设 `defending=true` → threshold +2 | AP 不足抛 `InsufficientAPError` |
| `item` | 0 | 委托 `ItemCallbackRouter` 调 `item.combatUse` | 未知 effectType 抛 `NeedsGMFallbackError` |
| `flee` | 0 | `d100 ≤ chance × 100` → `isFleeing=true` | 失败：状态不变，不扣 AP |
| `wait` | 0 | `applyAP(+1)`，受 `maxAp` clamp | — |

> **隐藏 `skill` 动作**：v0.5-dev 在 `CombatAction` 联合类型里**移除**了 `skill` 变体（`types.ts` 同步），`ActionResolver.resolveSkill` 已删除。SkillRegistry 落地后接回。

#### 2.6.6 战斗结束条件 (checkEndCondition)

| 条件 | outcome | 触发 |
|------|---------|------|
| `all_enemies_dead` | `victory` | 所有 enemy HP=0 |
| `player_dead` | `defeat` | 玩家 HP=0 / `isDead=true` |
| `fled` | `fled` | 玩家 `isFleeing=true` |
| `disrupted` | `disrupted` | 外部 toolcall 注入（GM 决策） |
| `gm_interrupted` | `interrupted` | 外部 toolcall 注入 |

#### 2.6.7 Buff 生命周期 (BuffManager)

```ts
interface BuffInstance {
  ref: string;              // ConditionsRegistry key
  stacks: number;           // 叠加层数 (默认 1)
  remainingTurns: number;   // -1 = 永久；正整数 = 剩余回合
  source: string;           // combatantId | itemId | 'system'
  appliedAtTurn: number;
  modifiers: Partial<Attributes>;
  onTick?: (c) => BuffTickResult;  // DOT/HOT 回调
  stackRule?: 'stack' | 'replace' | 'refresh' | 'ignore';  // 默认 'replace'
}
```

| stackRule | 行为 |
|-----------|------|
| `stack` | stacks 累加，modifiers 合并 |
| `refresh` | `remainingTurns = max(旧, 新)`，modifiers 用新的 |
| `ignore` | 已有同 ref 时忽略 |
| `replace`（默认）| 用新 buff 覆盖旧的 |

**`tickBuffs` 顺序**：onTick (DOT/HOT) → 倒计时 -1 → `remainingTurns=0` 时移除。由 `CombatEngine.processTurn` 在每个 action 之后调用。

#### 2.6.8 物品 effectType 战斗分类 (effectTypeCompat)

11 种 v0.3 `EffectType` 映射到 5 个战斗域分类：

| 分类 | EffectType | 战斗内处理 |
|------|-----------|------------|
| `heal` | `hp_restore` | ✅ `ItemCallbackRouter` 自动 |
| `buff` | `hp_max_bonus`, `vital_restore`, `attribute_mod`, `elemental_resist`, `skill_bonus` | ✅ 自动 |
| `damage` | `elemental_damage` | ✅ 自动 |
| `weapon-perm` | `damage_bonus`, `defense_bonus` | 走装备永久词条 |
| `gm-fallback` | `light_source`, `special`, 未知 | 抛 `NeedsGMFallbackError` 走 GM |

#### 2.6.9 回合内时序 (processTurn)

```
1. resolver.resolve(action, state)
   ├─ 命中投 / 命中门槛 / 伤害算
   ├─ 扣 AP/MP
   └─ 写 log
2. tickBuffs()             → DOT/HOT + 倒计时 -1
3. if (turn < queue.length) advanceTurn()
   else advanceRound() + clearDefendingFlags()
4. checkEndCondition()
   ├─ continue          → 等待下一动作
   └─ 非 continue       → beginResolving(outcome) + 写 end log
```

#### 2.6.10 4 档 → FailurePenalty

| 档 | damageTaken | goldLost% | conditions | survives |
|----|-------------|-----------|------------|----------|
| `trivial` | `none` | 0% | `[]` | true |
| `normal` | `minor` | 10% | `['wounded_1']` | true |
| `hard` | `major` | 30% | `['wounded_2', 'humiliated']` | true |
| `deadly` | `death-narrative` | 50% | `['wounded_3', 'humiliated', 'perma-wound']` | true |

- **`survives` 永远为 `true`**：deadly 档失败时 HP=0 不真死，进入"濒死剧情" + `perma-wound`
- 4 档 → 失败惩罚详细处理见 `BalanceEvaluator` + `CombatTools.endCombatHandler`

#### 2.6.11 校验契约 (`validateStartCombatArgs`)

- 6 维属性必须在 `[1, 20]`
- 必须有 `combatId` 字段
- `recommendedDifficulty ∈ {trivial, normal, hard, deadly}`
- 不合法时 tool result `ok = false`，带 `reason` 字段

#### 2.6.12 与原 §2.2/§2.3 文档的差异表

| 项 | 原 §2.2/§2.3 文档 | 代码实际（§2.6）| 说明 |
|----|------------------|----------------|------|
| `attack` AP | 1 | **2** | ACTION_COSTS.attack.ap = 2 |
| `defend` AP | 2 | **1** | DEFEND_AP_COST = 1 |
| `flee` AP | 2 | **0** | ACTION_COSTS.flee.ap = 0 |
| `item` AP | 1 | **0** | ACTION_COSTS.item.ap = 0 |
| `wait` 行为 | 留 AP | 恢复 1 AP | `applyAP(+1)` |
| `skill` 动作 | 1~4 AP | **已隐藏** | v0.5-dev 移除，待 SkillRegistry 接回 |
| 伤害公式 | d6 + STR/2 + weapon − defense | d6 + STR_mod + weapon − defense | STR_mod 替换 STR/2（D&D 风格） |
| 命中公式 | d20 + DEX/2 ≥ 10 + DEX/2 | d20 + STR_mod ≥ 10 + DEX_mod + defense + dodgePenalty + (defending ? 2 : 0) | DEX/2 → STR_mod（命中加值）；门槛加 defense + dodgePenalty + defending |
| 闪避模型 | 无 | 衰减型 (dodgePenalty +5/命中归零) | 久守必失 |

## 三、调试模式

### 3.1 入口

在标题页底部有一个低调的 **🐞 调试模式** 按钮（minimal 样式，不抢主按钮视线）。点击后弹出 4 张预设战斗卡。

调试模式用于开发与测试 v0.4 战斗系统各功能，**完全跳过 LLM**：点击战斗卡后，client 直接 dispatch `startCombat` toolcall，进入战斗 UI 立即可用，不需要 PM 引擎介入。

### 3.2 4 档预设

| 卡 | 难度 | 怪物 | 测试目标 |
|----|------|------|---------|

### 3.3 合成玩家

调试模式的玩家是**预设合成角色**"测试勇者"：

- **属性**：STR 14 / DEX 16 / CON 12 / INT 10 / WIS 15 / CHA 13
- **资源**：HP 30 / AP 6
- **装备**：铁剑（+4 攻击）、皮甲（+1 防御）、无饰品

合成玩家**完全独立**于你的真实角色存档：
- 不读取 `characterStore.character`
- 不写入 `characterStore`（即便战斗失败，金币 / 条件 / HP 都不会被改）
- 调试战斗**不污染**你的游戏进度

### 3.4 自动重开

战斗结束后（无论胜负），modal 会自动重开，让你可以立即再选一档。这是个开发效率设计——不需要每场战斗都点回标题页。

如需在战斗中退出，直接点 [X] 关闭 modal 即可。战斗会按 endCombat handler 的清理流程回归 `idle` 状态。

### 3.5 注意事项

- 调试模式只在标题页可用，战斗中无法打开新调试战斗
- 怪物工厂（`goblinScout` / `goblinWarrior` / `trollChief`）是测试用**固定数值**，不随 LLM 调参变化
- 调试战斗走完整的 5 阶段 FSM + 失败惩罚流程，**所有回归测试**都应能在此处复现

## 五、v0.4 增量

战斗系统是 v0.4 一次性交付的完整子系统，已记录在本文「二、设计」「三、调试模式」两章。本节汇总 v0.4 关键交付物与版本对齐信息。

### 5.1 组件清单 (7 个 UI + 4 个 service)

- **UI** — `CombatView` (主面板) / `CombatField` (战场) / `CombatantCard` (参战者卡) / `ActionMenu` (玩家行动菜单) / `ACTQueueBar` (先攻队列) / `QTETimingBar` / `QTETypingBox` (QTE 节奏 + 打字) / `FloatingDamage` / `CombatLog` (滚动日志)
- **Service** — `CombatEngine` (主引擎) / `ActionResolver` (命中 + 伤害) / `BalanceEvaluator` (平衡评估) / `BuffManager` (Buff/Debuff) / `QTELayer` (QTE 调度) / `ItemCallbackRouter` (物品钩子) / `combatTools` (toolcall 定义) / `debugCombatStarter` (Debug 入口) / `dice` (2d6 投骰) / `effectTypeCompat` (13 种 effectType 战斗兼容映射)
- **Store** — `combatStore` (战斗状态机: idle / setup / rolling / acting / resolution / ended)

### 5.2 状态机 (5 阶段)

```
idle → setup → rolling → acting → resolution → ended → idle
```

每阶段由 `CombatEngine` 推进, 玩家行动 (action menu 选 attack / skill / item / defend / flee) 触发 `ActionResolver` 计算命中与伤害, 命中后 `BalanceEvaluator` 评估双方均势, `BuffManager` 维护 buff/debuff 时序, `QTELayer` 在合适时机插入 QTE 节奏校验。

### 5.3 Debug Mode (与正式战斗隔离)

仅在标题页可用, 怪物工厂 `goblinScout` / `goblinWarrior` / `trollChief` 是固定数值, 调试战斗**不读不写** `characterStore`, 战斗结束 modal 自动重开便于反复回归。

### 5.4 GM 触发入口 (toolcall)

`PMEngine` 通过 toolcall `startCombat` / `endCombat` 把战斗与叙事融合:

- `startCombat({ enemies, party, terrain })` — 创建 combat session, 写入 `combatStore.session`
- `endCombat({ outcome, loot })` — 关闭 session, 物品按 v0.4 affix 池走 `applyConsequences.itemsGained`
